Introduction

Imagine you are writing a game and you need to track which direction a player is moving. You could use raw numbers like 0, 1, 2, and 3, but that makes your code impossible to read at a glance. You could use plain string constants, but nothing stops someone from passing in a typo like "Lefft". TypeScript enums solve this by giving named labels to a fixed set of values.

const enum takes that one step further. While a regular enum generates real JavaScript objects at runtime, a const enum is completely erased during compilation. TypeScript replaces every reference to a const enum member with its raw numeric value inline. The result is code that is just as readable while you write it, with zero runtime overhead once it ships.

In this lesson you will learn how to declare and use const enum, understand exactly what happens to your code when TypeScript compiles it, and see how this pattern maps cleanly to game development with ExcaliburJS.

Regular Enums vs. Const Enums

Before diving into const enum, it helps to see what a regular enum compiles to. Given this TypeScript: 


enum Direction {
  Up,
  Down,
  Left,
  Right,
}

TypeScript emits this JavaScript at runtime:


// Compiled output from a regular enum
var Direction;
(function (Direction) {
  Direction[Direction["Up"]    = 0] = "Up";
  Direction[Direction["Down"]  = 1] = "Down";
  Direction[Direction["Left"]  = 2] = "Left";
  Direction[Direction["Right"] = 3] = "Right";
})(Direction || (Direction = {}));

That is a real JavaScript object that exists at runtime. It supports reverse mapping (Direction[0] === "Up"), which is occasionally useful, but it adds weight to every bundle that includes it.

Now compare that to a const enum:


const enum Direction {
  Up,
  Down,
  Left,
  Right,
}

const playerDirection = Direction.Right;

TypeScript compiles the usage to:


// Compiled output — no object, just the inlined value
const playerDirection = 3; /* Direction.Right */
ℹ
Note

TypeScript often adds a trailing comment like /* Direction.Right */ to the compiled output so the inlined value stays readable during debugging.

Declaring a Const Enum

The syntax is identical to a regular enum with the single addition of the const keyword before enum: 


const enum GameState {
  MainMenu,     // 0
  Playing,      // 1
  Paused,       // 2
  GameOver,     // 3
}

By default, members are auto-numbered starting at 0. You can assign explicit values if the exact numbers matter:


const enum TileType {
  Empty   = 0,
  Wall    = 1,
  Floor   = 2,
  Spawn   = 3,
  Exit    = 4,
}

You can also use string values, though this is less common and removes the auto-increment behavior:


const enum AnimationKey {
  Idle   = "idle",
  Run    = "run",
  Jump   = "jump",
  Attack = "attack",
}
💡
Tip

Use string const enum values when the compiled output needs to match a specific string, such as animation keys that are passed to an asset loader by name. Use numeric values when the actual number is irrelevant and you only care about distinguishing states.

Using Const Enum Members

You reference members with dot notation, exactly like a regular enum. TypeScript enforces that only valid members are used:


const enum Direction {
  Up,
  Down,
  Left,
  Right,
}

function move(dir: Direction): void {
  if (dir === Direction.Up) {
    console.log("Moving up!");
  }
}

move(Direction.Left);   // OK
move(5);                // Error: Argument of type '5' is not assignable
                        //        to parameter of type 'Direction'

The type system treats Direction as a distinct type, so raw numbers that happen to be out of range are rejected. This is the main safety benefit over plain numeric constants.

Const Enum in a Switch Statement

Switch statements are where const enum really shines. TypeScript can warn you if you forget to handle a case, and the compiled output contains only simple number comparisons with no object lookup overhead: 


const enum GameState {
  MainMenu,
  Playing,
  Paused,
  GameOver,
}

function handleState(state: GameState): string {
  switch (state) {
    case GameState.MainMenu: return "Show title screen";
    case GameState.Playing:  return "Run game loop";
    case GameState.Paused:   return "Show pause menu";
    case GameState.GameOver: return "Show score screen";
  }
}

What You Cannot Do With Const Enums

Because const enum members are inlined and the object is erased, several runtime operations that work on regular enums will fail: 


const enum Direction { Up, Down, Left, Right }

// These all cause errors or produce undefined at runtime:

// 1. Reverse mapping does not exist
const name = Direction[0];  // TypeScript error

// 2. Iterating members is impossible
Object.keys(Direction);     // Error: 'const enum' members can only be
                            //         used in property access expressions

// 3. Passing the enum itself to a function
function logEnum(e: object) { console.log(e); }
logEnum(Direction);         // Error: 'Direction' only refers to a type
⚠
Warning

If you need to iterate over all values at runtime, display human-readable labels, or pass the enum object to a function, use a regular enum or a plain object constant instead. const enum is for read-only comparisons only.

Const Enum Across Files and Modules

const enum works reliably when everything is compiled together in one TypeScript project. However, there is one important caveat when consuming a const enum that is defined in a separate .d.ts declaration file (such as from a published npm package): TypeScript cannot inline values it cannot see at compile time. 


// If you import a const enum from a .d.ts-only package, you may see:
// error TS2748: Cannot access ambient const enums when
// 'isolatedModules' is enabled.
📌
Remember

When using build tools like Vite, esbuild, or Babel that process files one at a time, const enum defined in external packages can break. Stick to const enum within your own project source, or enable preserveConstEnums in your tsconfig.json if you need interop with external consumers.

Summary
  • A const enum is declared with the const keyword and produces zero runtime JavaScript because all members are inlined as literal values.
  • Members default to auto-incremented numbers starting at 0, but you can assign explicit numeric or string values.
  • TypeScript enforces that only valid enum members are used, giving you safety over bare number or string constants.
  • Because the object is erased, reverse mapping and runtime iteration are not available with const enum.
  • Avoid const enum across package boundaries or in projects that use single-file transpilers like esbuild unless you understand the tradeoffs.
  • In game code, const enum is ideal for naming states, directions, tile types, and any other closed set of values you compare but never iterate.

Introduction

One of the first decisions you face when shaping data in TypeScript is whether to reach for type or interface. Both let you describe the structure of an object, and at first glance they look nearly identical. This similarity trips up a lot of developers who either pick one arbitrarily or assume they are fully interchangeable.

In a game built with Excalibur, you will define shapes constantly: a player's stats, an enemy's configuration, a collectible item, an event payload. Picking the right tool up front keeps your code extensible and avoids subtle bugs that only appear once your game grows. By the end of this lesson you will know exactly which tool to reach for and why.

Type Aliases

A type alias gives a name to any TypeScript type. That includes object shapes, but also unions, intersections, primitives, tuples, and more. You declare one with the type keyword. 

// A simple object shape as a type alias
type PlayerStats = {
  health: number;
  speed: number;
  attackPower: number;
};

// Using the alias
const hero: PlayerStats = {
  health: 100,
  speed: 5,
  attackPower: 12,
};

Type aliases shine when you need to name something that is not an object shape. Unions and intersections are impossible to express with an interface. 

// Union: a collectible can be one of several kinds
type Collectible = "coin" | "gem" | "powerup";

// Intersection: merge two shapes into one
type BaseActor = { x: number; y: number };
type Labeled    = { name: string };
type NamedActor = BaseActor & Labeled;

const enemy: NamedActor = { x: 200, y: 300, name: "Goblin" };
💡
Tip

If you need a union (A | B) or a tuple ([string, number]), you must use a type alias. Interfaces cannot express those shapes.

Interfaces

An interface describes the shape of an object or class. It uses the interface keyword and is specifically designed for defining contracts that objects and classes can fulfill. 

// The same player shape as an interface
interface PlayerStats {
  health: number;
  speed: number;
  attackPower: number;
}

const hero: PlayerStats = {
  health: 100,
  speed: 5,
  attackPower: 12,
};

Interfaces support extension with the extends keyword, making inheritance chains clean and readable. This is especially useful when building on top of Excalibur's built-in types. 

interface BaseActorConfig {
  x: number;
  y: number;
}

interface EnemyConfig extends BaseActorConfig {
  health: number;
  speed: number;
  patrolRadius: number;
}

const goblin: EnemyConfig = {
  x: 400,
  y: 200,
  health: 50,
  speed: 3,
  patrolRadius: 100,
};

Key Differences

Declaration Merging

Interfaces support declaration merging: if you declare the same interface name twice, TypeScript merges them into one. Type aliases do not support this and will throw a compile error if you try. 

// Interface: second declaration merges into the first
interface ActorEvents {
  onCollide: () => void;
}

interface ActorEvents {
  onDeath: () => void;
}

// Result: ActorEvents now has BOTH onCollide and onDeath
const events: ActorEvents = {
  onCollide: () => console.log("hit!"),
  onDeath:   () => console.log("dead!"),
};

// Type alias: duplicate name is a compile error
type ActorEvents = { onCollide: () => void };
type ActorEvents = { onDeath:   () => void }; // Error: Duplicate identifier
⚠
Warning

Declaration merging is powerful but can be surprising. If you define the same interface in two different files and both are imported, TypeScript silently combines them. This is intentional behavior, but be aware that it is happening.

Extending vs Intersecting

Both tools support combining shapes, but the syntax differs. Interfaces use extends; type aliases use intersections (&). 

// Interface extension
interface Damageable {
  takeDamage(amount: number): void;
}

interface Enemy extends Damageable {
  patrol(): void;
}

// Type alias intersection (equivalent result)
type Damageable2 = { takeDamage: (amount: number) => void };
type Enemy2      = Damageable2 & { patrol: () => void };
ℹ
Note

extends and & are functionally similar for object shapes, but extends produces a clearer error message when a conflict exists between the two shapes. TypeScript will tell you exactly which property clashes.

What Only Type Aliases Can Do

// Primitives
type EntityId = string;

// Unions
type Direction = "up" | "down" | "left" | "right";

// Tuples
type Vec2 = [x: number, y: number];

// Conditional types
type NonNullable<T> = T extends null | undefined ? never : T;
📌
Remember

If your type involves anything other than a plain object shape (union, tuple, primitive alias, conditional), you need a type alias. Interfaces are strictly for object and class contracts.

Which One Should You Use?

Here is a practical decision rule you can apply immediately:

  • Use interface when you are defining an object or class contract that other code will implement or extend. This is the pattern Excalibur itself uses for actor options, engine configuration, and event maps.
  • Use type alias when you need anything a union, intersection of unrelated shapes, tuple, primitive rename, or conditional type.
  • When both would work, prefer interface for public-facing APIs (things other code extends) and type alias for internal, one-off shapes.
💡
Tip

Excalibur's source uses interfaces extensively for its configuration objects (like ActorArgs) so that you can extend them in your own project without forking the library. When you see an Excalibur type you want to build on top of, check whether it is an interface first.

Try It: Excalibur Playground

The snippet below sets up a minimal Excalibur scene using both an interface and a type alias. The interface defines an enemy's configuration contract. The type alias defines a union of possible enemy roles. Modify the code to add a new property to the interface and a new role to the union, then watch TypeScript enforce both shapes. 

import * as ex from "excalibur";

// Interface: a contract for configuring enemies
interface EnemyConfig {
  x: number;
  y: number;
  health: number;
  speed: number;
}

// Type alias: a union of valid enemy roles
type EnemyRole = "patrol" | "guard" | "boss";

// A factory function that uses both
function spawnEnemy(config: EnemyConfig, role: EnemyRole): ex.Actor {
  const actor = new ex.Actor({
    x: config.x,
    y: config.y,
    width: 32,
    height: 32,
    color: role === "boss" ? ex.Color.Red : ex.Color.Orange,
  });

  console.log(`Spawning ${role} with ${config.health} HP at (${config.x}, ${config.y})`);
  return actor;
}

const game = new ex.Engine({ width: 800, height: 600 });

game.start().then(() => {
  const enemy = spawnEnemy({ x: 400, y: 300, health: 80, speed: 3 }, "patrol");
  game.add(enemy);
});

Summary
  • Both type aliases and interface declarations can describe object shapes, and for plain objects they are mostly interchangeable.
  • Only type aliases can express unions, tuples, primitive renames, and conditional types.
  • Only interfaces support declaration merging, which allows multiple declarations of the same name to be combined automatically.
  • Use interface for object or class contracts that other code will extend or implement; use type for anything else.
  • Excalibur uses interfaces for its configuration objects, so you can extend them cleanly with extends without modifying the library.

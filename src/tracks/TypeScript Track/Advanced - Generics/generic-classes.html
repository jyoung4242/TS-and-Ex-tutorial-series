Introduction

Imagine you are building a game inventory system. You need a container that can hold swords, potions, or armor, but you want TypeScript to stop you from accidentally putting a Potion into a slot reserved for Weapon objects. You could write a separate class for each item type, but that means copy-pasting the same logic dozens of times. Generic classes solve this: you write the container once, and TypeScript fills in the item type at the call site.

Generic classes extend the same idea as generic functions, but they attach the type parameter to the whole class rather than to a single method. Every property and method inside the class can then reference that type, giving you end-to-end type safety across the entire object lifetime.

In ExcaliburJS projects you will reach for generic classes constantly: typed component stores, object pools, event queues, and resource caches are all natural fits. By the end of this lesson you will be able to write all of them with confidence.

What Is a Generic Class?

A generic class declares one or more type parameters in angle brackets right after the class name. Those parameters act like placeholders that get replaced with a concrete type when the class is instantiated. The syntax looks like this: 

class Box<T> {
  private value: T;

  constructor(value: T) {
    this.value = value;
  }

  getValue(): T {
    return this.value;
  }
}

const numberBox = new Box<number>(42);
const nameBox   = new Box<string>("Hero");

console.log(numberBox.getValue()); // 42
console.log(nameBox.getValue());   // "Hero"

T is just a name. By convention, single-letter names like T (type), K (key), V (value), and E (element) are common, but you can use any valid identifier. Descriptive names like TItem or TPayload help when there are multiple parameters.

ℹ
Note

TypeScript can often infer the type parameter from the constructor argument, so new Box(42) is equivalent to new Box<number>(42). Explicit annotation is still a good habit when the intent might not be obvious.

Multiple Type Parameters

A class can declare more than one type parameter, separated by commas. A common use case is a key-value store where both the key type and the value type need to be flexible. 

class GameRegistry<K, V> {
  private entries = new Map<K, V>();

  register(key: K, value: V): void {
    this.entries.set(key, value);
  }

  lookup(key: K): V | undefined {
    return this.entries.get(key);
  }

  get size(): number {
    return this.entries.size;
  }
}

// Keys are strings, values are numbers (scores)
const scoreBoard = new GameRegistry<string, number>();
scoreBoard.register("Player1", 1500);
scoreBoard.register("Player2", 980);

console.log(scoreBoard.lookup("Player1")); // 1500

Constraining Type Parameters with extends

Unconstrained type parameters are maximally flexible, but sometimes you need to guarantee that the type has certain properties. You add a constraint with the extends keyword. The constraint is a type (or interface) that any supplied type must satisfy. 

interface HasName {
  name: string;
}

class EntityStore<T extends HasName> {
  private items: T[] = [];

  add(item: T): void {
    this.items.push(item);
  }

  findByName(name: string): T | undefined {
    return this.items.find(item => item.name === name);
  }

  getAll(): T[] {
    return [...this.items];
  }
}

interface Enemy {
  name: string;
  health: number;
}

const enemies = new EntityStore<Enemy>();
enemies.add({ name: "Goblin", health: 30 });
enemies.add({ name: "Dragon", health: 500 });

const dragon = enemies.findByName("Dragon");
console.log(dragon?.health); // 500

Without the constraint, TypeScript would not let you access item.name inside findByName because it would not know that T has a name property. The constraint makes that property available throughout the class body.

💡
Tip

Prefer constraining to an interface rather than a concrete class when possible. This keeps the generic class open to any object that has the required shape, not just instances of one particular class hierarchy.

Generic Methods Inside Generic Classes

Methods on a generic class automatically have access to the class-level type parameter. They can also introduce their own additional type parameters for operations that need extra flexibility. Keep the distinction clear: class-level T describes the data the class stores; method-level parameters describe one-off transformations. 

class DataPipeline<T> {
  private data: T[] = [];

  push(item: T): this {
    this.data.push(item);
    return this;
  }

  // Method-level type parameter R is independent of class-level T
  map<R>(transform: (item: T) => R): DataPipeline<R> {
    const next = new DataPipeline<R>();
    this.data.forEach(item => next.push(transform(item)));
    return next;
  }

  toArray(): T[] {
    return [...this.data];
  }
}

const scores = new DataPipeline<number>()
  .push(100)
  .push(250)
  .push(75);

const labels = scores.map(n => `Score: ${n}`);
console.log(labels.toArray()); // ["Score: 100", "Score: 250", "Score: 75"]
⚠
Warning

Static members of a class cannot reference the class-level type parameter because static members belong to the class itself, not to any particular instance. If you need a generic static factory method, give that method its own type parameter. 

class Pool<T> {
  private items: T[] = [];

  // ERROR: static method cannot use class-level T
  // static create(item: T): Pool<T> { ... }

  // Correct: static method declares its own parameter
  static create<U>(item: U): Pool<U> {
    const pool = new Pool<U>();
    pool.items.push(item);
    return pool;
  }

  checkout(): T | undefined {
    return this.items.pop();
  }

  checkin(item: T): void {
    this.items.push(item);
  }
}

A Real Pattern: Generic Object Pool in ExcaliburJS

Object pooling is a core performance technique in game development. Rather than creating and destroying objects every frame, you reuse them. A generic pool class lets you pool any game object type with a single, well-tested implementation. 

import { Actor } from "excalibur";

interface Poolable {
  reset(): void;
  active: boolean;
}

class ObjectPool<T extends Poolable> {
  private available: T[] = [];
  private inUse: Set<T> = new Set();
  private readonly factory: () => T;

  constructor(factory: () => T, initialSize = 10) {
    this.factory = factory;
    for (let i = 0; i < initialSize; i++) {
      this.available.push(factory());
    }
  }

  acquire(): T {
    const item = this.available.pop() ?? this.factory();
    item.active = true;
    this.inUse.add(item);
    return item;
  }

  release(item: T): void {
    if (!this.inUse.has(item)) return;
    item.active = false;
    item.reset();
    this.inUse.delete(item);
    this.available.push(item);
  }

  get activeCount(): number {
    return this.inUse.size;
  }
}

// Usage with a bullet actor
class Bullet extends Actor implements Poolable {
  active = false;

  reset(): void {
    this.pos.setTo(0, 0);
    this.vel.setTo(0, 0);
    this.active = false;
  }
}

const bulletPool = new ObjectPool<Bullet>(() => new Bullet(), 20);
const bullet = bulletPool.acquire();
// ... position and fire bullet ...
bulletPool.release(bullet);
📌
Remember

The constraint T extends Poolable guarantees that every item in the pool has a reset() method and an active property. Without the constraint, the pool body could not safely call those members.

Summary
  • A generic class declares type parameters after the class name; those parameters apply to every property and method in the class body.
  • Use extends to constrain a type parameter so the class body can safely access specific properties or methods on T.
  • Static members cannot reference class-level type parameters; give static factory methods their own independent type parameters instead.
  • Methods inside a generic class can introduce additional type parameters for transformations that produce a different output type, such as a map operation.
  • Object pools, component stores, event queues, and registries are all natural uses for generic classes in ExcaliburJS game projects.
  • When a class only ever holds one fixed type, a plain typed class is simpler; reach for generics only when the type needs to vary at the call site.

Introduction

Generic type parameters let you write flexible, reusable code. But sometimes a generic alone is not enough: you want the output type to change based on what the input type looks like. That is exactly what conditional types give you.

Think about a game loader that accepts either a Promise<Sprite> or a plain Sprite. Regardless of which form you pass in, you want to end up with just Sprite. Without conditional types you end up with two overloads or a manual union. With them, a single generic type handles the unwrapping automatically, and the compiler enforces it.

This lesson builds conditional types from first principles, introduces the infer keyword that makes them truly powerful, and shows how TypeScript's built-in utility types like ReturnType and Parameters are written using these same ideas.

Conditional Types: T extends U ? X : Y

A conditional type is a ternary expression at the type level. TypeScript asks: "does T satisfy the constraint U?" If yes, the whole type resolves to X; if no, it resolves to Y. 

// The basic shape
type IsString<T> = T extends string ? "yes" : "no";

type A = IsString<string>;   // "yes"
type B = IsString<number>;   // "no"
type C = IsString<"hello">;  // "yes" — literal "hello" extends string
ℹ
Note

extends inside a conditional type does not mean inheritance the way it does in a class. It means "is assignable to" or "is a subtype of." A string literal is assignable to string, so "hello" extends string is true.

Chaining conditionals

You can nest conditional types just like nested ternaries in JavaScript. Keep them shallow enough to stay readable.

type TypeName<T> =
  T extends string  ? "string"  :
  T extends number  ? "number"  :
  T extends boolean ? "boolean" :
  T extends object  ? "object"  :
  "other";

type T1 = TypeName<42>;      // "number"
type T2 = TypeName<boolean>; // "boolean"
type T3 = TypeName<symbol>;  // "other"
💡
Tip

Hover over T1, T2, and T3 in your editor. TypeScript will eagerly evaluate and display the resolved string literal type, which makes conditional types much easier to debug than you might expect.

Extracting Types with infer

The real superpower of conditional types arrives when you combine them with the infer keyword. Instead of testing whether a type matches a shape and then hard-coding what to return, you can ask TypeScript to capture a piece of that shape and name it so you can use it on the right-hand side. 

// Without infer — you can check, but you cannot extract
type IsArray<T> = T extends Array<unknown> ? "yes" : "no";

// With infer — you can check AND extract the element type
type ElementOf<T> = T extends Array<infer Item> ? Item : never;

type E1 = ElementOf<string[]>;         // string
type E2 = ElementOf<number[]>;         // number
type E3 = ElementOf<(Sprite | Actor)[]>; // Sprite | Actor
type E4 = ElementOf<string>;           // never (not an array)

infer Item tells TypeScript: "if this matches, bind whatever fills the Item slot to the name Item, and make that name available in the true branch." The name you choose is a local type variable scoped to that conditional.

📌
Remember

infer is only valid inside the extends clause of a conditional type. You cannot use it outside that context. Think of it as pattern matching: TypeScript tries to match the shape and, if it succeeds, fills in the named slots you declared with infer.

Unwrapping a Promise

One of the most common uses for infer is stripping the Promise wrapper from an async value. This pattern shows up constantly in game loaders, asset pipelines, and any code that bridges async loading with synchronous game logic. 

type Awaited<T> = T extends Promise<infer Value> ? Value : T;

type A = Awaited<Promise<Sprite>>; // Sprite
type B = Awaited<Promise<number>>; // number
type C = Awaited<Sprite>;          // Sprite  (not a Promise, passthrough)
ℹ
Note

TypeScript 4.5+ ships Awaited<T> as a built-in utility type, and it handles deeply nested promises recursively. The version above is a simplified illustration. The principle is identical.

Extracting function shapes

You can infer from any structural position: tuple slots, function parameters, return types, constructor signatures, and more.

// Recreating TypeScript's built-in ReturnType
type MyReturnType<T extends (...args: any[]) => any>
  = T extends (...args: any[]) => infer R ? R : never;

// Recreating TypeScript's built-in Parameters
type MyParameters<T extends (...args: any[]) => any>
  = T extends (...args: infer P) => any ? P : never;

// ---- usage in game code ----
type SpawnFn = (x: number, y: number, label: string) => Actor;

type SpawnReturn = MyReturnType<SpawnFn>;   // Actor
type SpawnArgs   = MyParameters<SpawnFn>;   // [number, number, string]
💡
Tip

MyReturnType and MyParameters above are exactly how TypeScript's standard library defines them. If you understand this pattern, you can read and extend any utility type in lib.d.ts.

Distributive Conditional Types

When you pass a union type to a conditional type and the type parameter is "naked" (not wrapped in another type), TypeScript automatically distributes the conditional over each union member. 

type ToArray<T> = T extends any ? T[] : never;

type Result = ToArray<string | number>;
// TypeScript distributes this as:
// ToArray<string> | ToArray<number>
// => string[] | number[]

Distribution is usually what you want. But sometimes you need to suppress it, for example when you want to check whether a union as a whole extends something. Wrap the type parameter in a one-element tuple to opt out. 

// Distributed — checks each member individually
type IsStringDist<T> = T extends string ? true : false;
type D = IsStringDist<string | number>; // boolean (true | false)

// Non-distributed — checks the union as a unit
type IsStringFull<T> = [T] extends [string] ? true : false;
type F = IsStringFull<string | number>; // false
⚠
Warning

Distribution only happens when the type parameter is bare on the left side of extends. Writing T[], [T], or Promise<T> on the left side disables distribution. This catches people by surprise when they wrap the parameter for reasons unrelated to distribution.

Filtering union members

Distribution lets you build a filter that removes union members that do not meet a condition. The built-in Extract and Exclude utility types work this way. 

// Keep only members that extend Filter
type MyExtract<T, Filter> = T extends Filter ? T : never;

// Remove members that extend Excluded
type MyExclude<T, Excluded> = T extends Excluded ? never : T;

type Events = "keydown" | "keyup" | "mousedown" | "mousemove";

type KeyEvents   = MyExtract<Events, `key${string}`>;
// "keydown" | "keyup"

type MouseEvents = MyExclude<Events, `key${string}`>;
// "mousedown" | "mousemove"

Patterns in ExcaliburJS Game Code

Game engines produce exactly the kind of layered, polymorphic data that conditional types are designed to handle. Here are three patterns you will encounter when working with ExcaliburJS.

Normalizing a mixed asset argument

import { Sprite, ImageSource } from "excalibur";

// A loader might accept a raw source or a pre-built sprite
type NormalizeAsset<T> =
  T extends ImageSource ? Sprite :
  T extends Sprite       ? Sprite :
  never;

function loadAsset<T extends ImageSource | Sprite>(
  asset: T
): NormalizeAsset<T> {
  if (asset instanceof ImageSource) {
    return asset.toSprite() as NormalizeAsset<T>;
  }
  return asset as NormalizeAsset<T>;
}

const a = loadAsset(new ImageSource("/hero.png")); // Sprite
const b = loadAsset(new Sprite({ /* ... */ }));    // Sprite

Inferring component data type from a tag

// Imagine a small component registry
interface ComponentMap {
  health:   { current: number; max: number };
  velocity: { vx: number; vy: number };
  label:    { text: string };
}

type ComponentData<T extends keyof ComponentMap> =
  ComponentMap[T] extends infer D ? D : never;

type HealthData   = ComponentData<"health">;   // { current: number; max: number }
type VelocityData = ComponentData<"velocity">; // { vx: number; vy: number }

Deep-unwrapping an async resource

// Recursively unwrap nested promises (matches TypeScript's built-in Awaited)
type DeepAwaited<T> =
  T extends Promise<infer Inner>
    ? DeepAwaited<Inner>
    : T;

type Result = DeepAwaited<Promise<Promise<Sprite>>>; // Sprite
💡
Tip

TypeScript limits recursive conditional type depth to prevent infinite loops at compile time. For most game use cases the default limit is more than sufficient, but keep recursion shallow whenever you can.

Summary
  • Conditional types use T extends U ? X : Y to make a type resolve differently based on what T looks like at compile time.
  • The infer keyword lets you capture and name a piece of a matched type inside the true branch, enabling patterns like Awaited, ReturnType, and Parameters.
  • When a bare type parameter is passed a union, TypeScript distributes the conditional over each member automatically; wrapping the parameter in a tuple like [T] suppresses this behavior.
  • Built-in utility types including Extract, Exclude, ReturnType, and Parameters are all written with conditional types and infer using the same patterns covered here.
  • In ExcaliburJS code, conditional types shine when normalizing mixed asset inputs, inferring component data shapes from registry keys, and unwrapping async loader return values.

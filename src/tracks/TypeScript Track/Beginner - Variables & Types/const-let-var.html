Introduction

Every useful program stores data. In TypeScript, you store data in variables, and the keyword you choose to declare that variable matters more than it might seem. Pick the wrong one and you can end up with bugs that are surprisingly hard to track down.

TypeScript gives you three keywords for declaring variables: const, let, and var. If you are coming from older JavaScript, you may have used var everywhere. Modern TypeScript has better options. By the end of this lesson you will know exactly which keyword to reach for and why.

const: Your Default Choice

const declares a variable whose binding cannot be reassigned. Once you assign a value to a const variable, you cannot point that variable at a different value. This makes your intentions clear to anyone reading the code: this value is not going to change. 


const playerName: string = "Aria";
const maxHealth: number = 100;
const isAlive: boolean = true;

// This would cause a TypeScript error:
// playerName = "Zed"; // Error: Cannot assign to 'playerName' because it is a constant.
ℹ
Note

const prevents reassignment of the variable itself, but it does not make objects or arrays immutable. You can still mutate the contents of a const object. 


const player = {
  name: "Aria",
  health: 100,
};

// This is allowed -- we are mutating the object, not reassigning the variable:
player.health = 80;

// This is NOT allowed -- we are trying to reassign the variable itself:
// player = { name: "Zed", health: 100 }; // Error
💡
Tip

Use const by default for every variable you declare. Only switch to let when you know the variable will need to be reassigned. This habit reduces bugs and makes code easier to reason about.

let: When Values Need to Change

let declares a variable that can be reassigned. Use it when the value genuinely needs to change over the lifetime of the variable, such as a score that increases, a counter in a loop, or a status that toggles. 


let score: number = 0;
let currentLevel: number = 1;

score = score + 10;   // Allowed
currentLevel = 2;     // Allowed

Block Scope

Both const and let are block-scoped. A block is any section of code wrapped in curly braces { }. A variable declared inside a block only exists within that block. 


function updateScore(points: number): void {
  let score: number = 0;

  if (points > 0) {
    let bonus: number = points * 2; // 'bonus' only exists inside this if-block
    score = score + bonus;
  }

  // console.log(bonus); // Error: 'bonus' is not defined here
  console.log(score);    // Works fine
}
📌
Remember

Block scope means variables live exactly where you declare them and nowhere else. This is predictable and safe. Always prefer block-scoped variables.

let in Loops

let is the right choice for loop counters because the counter value changes on every iteration.


const enemies: string[] = ["Goblin", "Orc", "Dragon"];

for (let i: number = 0; i < enemies.length; i++) {
  console.log(`Enemy ${i + 1}: ${enemies[i]}`);
}

// 'i' does not exist here -- it was scoped to the for loop block

var: The Old Way (Avoid It)

var is the original JavaScript variable declaration keyword. It predates const and let, and it has two behaviors that cause real bugs: function scope and hoisting.

Function Scope (Not Block Scope)

Unlike const and let, var is scoped to the nearest function, not the nearest block. This means a var declared inside an if block leaks out into the whole function. 


function checkHealth(health: number): void {
  if (health <= 0) {
    var message: string = "Game Over"; // declared inside the if-block...
  }

  console.log(message); // ...but accessible out here! Prints "Game Over" or undefined
}

With let, the same code would throw an error at the console.log line, which is exactly what you want. The bug becomes visible immediately instead of silently producing undefined.

Hoisting

var declarations are hoisted to the top of their containing function. This means you can reference a var variable before the line where you declared it, and it will not throw an error. It will just be undefined. 


function demonstrateHoisting(): void {
  console.log(enemy); // Prints: undefined (no error -- but this is a bug waiting to happen)
  var enemy: string = "Goblin";
  console.log(enemy); // Prints: "Goblin"
}

TypeScript compiles down to JavaScript, and this hoisting behavior is inherited from JavaScript. With let or const, referencing a variable before its declaration is a compile-time error, which is much safer.

⚠
Warning

Do not use var in new TypeScript code. It exists only for backwards compatibility with old JavaScript. The TypeScript compiler will even warn you if you enable the noVar linting rule. Always use const or let instead.

Comparison at a Glance

Keyword Reassignable? Scope Hoisted? Use it?
const No Block No Yes, by default
let Yes Block No Yes, when value changes
var Yes Function Yes No, avoid it

Summary
  • Use const by default. It prevents reassignment and signals that a value is fixed.
  • Use let when a variable genuinely needs to be reassigned, such as a counter or running total.
  • Both const and let are block-scoped, meaning they exist only within the curly braces where they are declared.
  • Avoid var. Its function scope and hoisting behavior lead to subtle bugs that block-scoped declarations prevent entirely.
  • const on an object prevents reassigning the variable, but the object's properties can still be mutated.

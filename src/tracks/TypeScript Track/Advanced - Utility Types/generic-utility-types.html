Introduction

Imagine you have a PlayerConfig type with a dozen properties: position, speed, health, sprite sheet, animations, and so on. Now you need a second type for a save-game patch object where every property is optional. And a third type for a read-only snapshot you pass to a renderer. Do you copy-paste the original and add ? everywhere? That approach works until the original changes and you forget to update the copies.

TypeScript ships with a library of generic utility types that solve exactly this problem. They are generic because they accept a type as an argument, and they are utility types because their only job is to transform that input type into a new one. No runtime code, no imports, no installation: just expressive, maintainable type-level logic.

By the end of this lesson you will reach for these utilities the way you reach for Array.map: automatically, because you know what they do and trust them to do it cleanly.

What Makes a Type Generic?

A generic type is a type that takes a type parameter the same way a function takes a value parameter. The angle-bracket syntax <T> is the signal. 

// A generic identity type -- takes any type T and returns it unchanged
type Identity<T> = T;

type MyString = Identity<string>; // string
type MyNumber = Identity<number>; // number

TypeScript's built-in utility types follow the same pattern. They accept one or more type parameters and produce a derived type. You never have to implement them yourself -- they live in TypeScript's standard library and are always in scope.

ℹ
Note

Utility types operate purely at compile time. They have zero runtime cost and produce zero JavaScript output. They exist only to help the type checker reason about your code.

Partial<T> and Required<T>

Partial<T> takes every property of T and makes it optional. Required<T> does the opposite: it strips the ? from every property and forces them all to be present. 

interface ActorConfig {
  x: number;
  y: number;
  width: number;
  height: number;
  color?: string;
}

// All properties become optional -- good for patch/update objects
type ActorPatch = Partial<ActorConfig>;
// { x?: number; y?: number; width?: number; height?: number; color?: string }

// All properties become required -- color is no longer optional
type StrictActorConfig = Required<ActorConfig>;
// { x: number; y: number; width: number; height: number; color: string }

function updateActor(id: string, patch: ActorPatch): void {
  // caller only needs to supply the fields that changed
}

updateActor("player", { x: 100 }); // valid -- only x is changing
💡
Tip

Partial is ideal for update functions and config merging. If you find yourself writing the same interface twice with all the same fields but every one marked ?, reach for Partial instead.

Readonly<T>

Readonly<T> marks every property of T as readonly, preventing reassignment after construction. This is useful for snapshot objects, immutable configs, or state that should never be mutated once created. 

interface GameState {
  score: number;
  level: number;
  lives: number;
}

type FrozenState = Readonly<GameState>;

const snapshot: FrozenState = { score: 1200, level: 3, lives: 2 };

// TypeScript error: Cannot assign to 'score' because it is a read-only property.
snapshot.score = 9999;
⚠
Warning

Readonly<T> is shallow. If a property is itself an object, the nested object's properties are still mutable. For deep immutability you need a recursive type or a library like ts-essentials.

Pick<T, K> and Omit<T, K>

Sometimes you need a subset of an existing type. Pick lets you select the properties you want by name. Omit lets you exclude the properties you do not want, keeping everything else. 

interface Enemy {
  id: string;
  name: string;
  health: number;
  damage: number;
  spriteSheet: string;
  aiPattern: string;
}

// Keep only the fields the HUD needs to display
type EnemyHUDData = Pick<Enemy, "name" | "health">;
// { name: string; health: number }

// Strip internal fields before sending to a save file
type SerializableEnemy = Omit<Enemy, "spriteSheet" | "aiPattern">;
// { id: string; name: string; health: number; damage: number }
📌
Remember

Pick is additive: you name what you want. Omit is subtractive: you name what you do not want. When the list of fields to keep is shorter, use Pick. When the list of fields to drop is shorter, use Omit.

Composing Pick and Partial Together

Utility types are composable. Wrap one inside another to express layered constraints without writing a new interface.

// A patch type that only touches display-related fields
type EnemyDisplayPatch = Partial<Pick<Enemy, "name" | "health" | "spriteSheet">>;
// { name?: string; health?: number; spriteSheet?: string }

function patchEnemyDisplay(id: string, changes: EnemyDisplayPatch): void {
  // safe: only display fields can be modified, and all are optional
}

ReturnType<T>

ReturnType<T> extracts the return type of a function type. This is valuable when you need to reference what a function produces without importing or duplicating its return type definition. 

function createPlayer(name: string, startX: number, startY: number) {
  return {
    name,
    position: { x: startX, y: startY },
    health: 100,
    score: 0,
  };
}

// Infer the shape from the function itself -- no manual interface needed
type Player = ReturnType<typeof createPlayer>;
// { name: string; position: { x: number; y: number }; health: number; score: number }

function displayPlayerInfo(player: Player): void {
  console.log(`${player.name} at (${player.position.x}, ${player.position.y})`);
}
ℹ
Note

Notice the typeof keyword: ReturnType takes a type, not a value. typeof createPlayer converts the value (the function) into its type so ReturnType can inspect it.

Quick Reference

Here is the full set of utility types covered in this lesson at a glance:

Utility Type What It Does Common Use Case
Partial<T> Makes all properties optional Patch / update objects
Required<T> Makes all properties required Strict config validation
Readonly<T> Prevents all property reassignment Immutable snapshots, frozen state
Pick<T, K> Keeps only the listed properties View models, HUD data
Omit<T, K> Removes the listed properties Serialization, stripping internals
ReturnType<T> Extracts a function's return type Inferring factory output shapes

Summary
  • Generic utility types accept a type parameter and return a transformed type -- they are type-level functions built into TypeScript with zero runtime cost.
  • Partial and Required toggle optionality across all properties at once, making them ideal for update and validation patterns.
  • Readonly enforces immutability at the property level, though it is shallow and does not protect nested objects.
  • Pick and Omit carve subsets from an existing type: Pick is additive, Omit is subtractive.
  • Record<K, V> builds an exhaustive typed dictionary; when K is a string literal union, TypeScript ensures no key is missing.
  • ReturnType<typeof fn> extracts a function's inferred return shape, removing the need to duplicate type definitions for factory outputs.
  • Utility types compose: wrapping one inside another (like Partial<Pick<T, K>>) lets you express layered constraints in a single, readable alias.

Introduction

Imagine you are designing an enemy actor for a game. The enemy has a health value, an internal damage multiplier, and a public method to take damage. If any other system in your game can directly set enemy.health = 9999 or enemy.damageMultiplier = 0, bugs become nearly impossible to track down. You intended those fields to be internal details, but nothing stopped outside code from reaching in and changing them.

Access modifiers are TypeScript's solution. They let you mark which parts of a class are part of its public contract and which are private implementation details. The result is a clear boundary: other systems call the methods you expose, and the internals stay yours to control.

In this lesson you will learn the three core modifiers (public, private, protected), the readonly modifier, and a convenient shorthand that keeps constructors tidy. Every example is grounded in patterns you will actually use with ExcaliburJS actors and components.

The public Modifier

public is the default for every class member. Marking something public means any code, inside or outside the class, can read or write it. You rarely need to write the keyword explicitly, but doing so is good documentation when you are being deliberate about your API. 


class PlayerActor {
  public name: string;       // explicitly public
  score: number;             // also public -- the keyword is optional

  constructor(name: string) {
    this.name = name;
    this.score = 0;
  }

  public addScore(points: number): void {
    this.score += points;
  }
}

const player = new PlayerActor("Ada");
player.name = "Ada Lovelace"; // OK -- public
player.addScore(100);         // OK -- public method
ℹ
Default visibility

TypeScript class members are public when no modifier is specified. Many style guides omit the keyword on public members to reduce noise, and add it only as documentation on methods that form a deliberate public API.

The private Modifier

private restricts access to the class body itself. No subclass, no external caller, nothing outside the curly braces of the class definition can read or write a private member. TypeScript will raise a type error at compile time if you try. 


class EnemyActor {
  public label: string;
  private health: number;
  private damageMultiplier: number;

  constructor(label: string, health: number) {
    this.label = label;
    this.health = health;
    this.damageMultiplier = 1.0;
  }

  // The only sanctioned way to reduce health
  public takeDamage(amount: number): void {
    const actual = amount * this.damageMultiplier;
    this.health = Math.max(0, this.health - actual);
  }

  public isDefeated(): boolean {
    return this.health <= 0;
  }
}

const goblin = new EnemyActor("Goblin", 80);
goblin.takeDamage(20);        // OK -- public method
goblin.health = 9999;         // Error: Property 'health' is private
goblin.damageMultiplier = 0;  // Error: Property 'damageMultiplier' is private

Now health can only change through takeDamage. You control every path of mutation, which makes the class far easier to reason about and debug.

⚠
Compile-time only

TypeScript's private keyword is erased when compiled to JavaScript. At runtime, the property still exists on the object and is technically accessible. If you need genuine runtime privacy, use the ECMAScript #field syntax (#health), which is enforced by the JavaScript engine itself. For most TypeScript projects, the compile-time check is sufficient.

The protected Modifier

protected sits between private and public. A protected member is inaccessible to outside code, but subclasses can read and write it. This is useful when you have a base class that encapsulates shared logic and subclasses that legitimately need to extend that behavior. 


class BaseActor {
  public label: string;
  protected health: number;   // subclasses can access this

  constructor(label: string, health: number) {
    this.label = label;
    this.health = health;
  }

  public takeDamage(amount: number): void {
    this.health = Math.max(0, this.health - amount);
  }

  public isDefeated(): boolean {
    return this.health <= 0;
  }
}

class BossActor extends BaseActor {
  private phase: number = 1;

  // A boss can react to its own health state
  public takeDamage(amount: number): void {
    super.takeDamage(amount);

    // OK -- BossActor can read this.health because it is protected
    if (this.health < 50 && this.phase === 1) {
      this.phase = 2;
      console.log(`${this.label} enters phase 2!`);
    }
  }
}

const boss = new BossActor("Dragon", 100);
boss.takeDamage(60);   // logs "Dragon enters phase 2!"
boss.health;           // Error: Property 'health' is protected
💡
When to choose protected vs private

Start with private. Upgrade to protected only when you are deliberately designing a base class that expects subclasses to build on it. Opening up a field to subclasses is a conscious architectural decision, not a default.

The readonly Modifier

readonly allows a field to be set once, during construction, and then prevents any further mutation. It can be combined with any visibility modifier. This is ideal for fields that represent permanent identity, like an actor's unique ID or its scene assignment. 


class ActorComponent {
  public readonly id: string;
  private readonly ownerId: string;

  constructor(id: string, ownerId: string) {
    this.id = id;
    this.ownerId = ownerId;
  }

  public describe(): string {
    return `Component ${this.id} owned by ${this.ownerId}`;
  }
}

const comp = new ActorComponent("health-bar", "player-1");
console.log(comp.id);       // "health-bar" -- OK, reading is fine
comp.id = "renamed";        // Error: Cannot assign to 'id' because it is a read-only property
📌
readonly is not const

const applies to variable bindings. readonly applies to class properties. A readonly array field still lets you call .push() on the array itself, because the binding has not changed. To prevent mutation of an array's contents, combine readonly with ReadonlyArray<T>.

Constructor Parameter Shorthand

TypeScript lets you declare and assign class fields directly in the constructor parameter list. Add an access modifier (or readonly) in front of the parameter name and TypeScript automatically creates the field and assigns the value. This eliminates a lot of repetitive boilerplate. 


// Without shorthand -- four separate steps
class ActorLong {
  public label: string;
  private health: number;
  protected speed: number;
  public readonly id: string;

  constructor(label: string, health: number, speed: number, id: string) {
    this.label = label;
    this.health = health;
    this.speed = speed;
    this.id = id;
  }
}

// With shorthand -- same result, far less code
class ActorShort {
  constructor(
    public label: string,
    private health: number,
    protected speed: number,
    public readonly id: string,
  ) {}

  public takeDamage(amount: number): void {
    this.health = Math.max(0, this.health - amount);
  }
}

Both classes are identical in the compiled output. The shorthand is the standard pattern in TypeScript codebases because it keeps constructors concise and keeps the field declaration and its initialization in one place.

💡
Mixing shorthand and manual fields

You can mix shorthand parameters with fields that need more complex initialization. Use shorthand for straightforward assignments and write a manual assignment inside the constructor body when you need to compute or transform the value before storing it.

Summary
  • public is the default: any code can read or write the member. Use it deliberately to define what your class intentionally exposes.
  • private restricts access to the class body only. Subclasses cannot access private members, which keeps implementation details truly internal.
  • protected extends access to subclasses while still blocking outside callers. Use it when designing a base class meant to be extended.
  • readonly allows assignment only in the constructor. Combine it with any visibility modifier to model fields that represent permanent identity.
  • Constructor parameter shorthand (placing a modifier before a constructor parameter) declares and assigns the field automatically, reducing boilerplate significantly.
  • TypeScript access modifiers are compile-time only. Use ECMAScript private fields (#field) when you need runtime enforcement in the JavaScript output.

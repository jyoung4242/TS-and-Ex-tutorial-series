  • Call parent constructors and methods with super() correctly and in the right order

  • Annotate inherited properties with protected so subclasses can access them safely
  • Apply class inheritance to real Excalibur actor hierarchies like enemy types and projectile variants

Introduction

Imagine you're building a game with a dozen enemy types. Each one has health, a position, and a takeDamage() method. Without inheritance you'd copy that logic into every class and fix the same bug twelve times. Class inheritance lets you define that shared behavior once in a base class, then extend it for each specialized type.

TypeScript builds cleanly on JavaScript's class model and adds compile-time safety around the features that trip developers up most: calling super() before touching this, narrowing access with protected, and type-checking overridden method signatures. In this lesson you'll understand exactly how those pieces fit together.

The extends Keyword

A subclass inherits all public and protected members of its parent. Use the extends keyword to declare the relationship. 

class Actor {
  name: string;
  x: number;
  y: number;

  constructor(name: string, x: number, y: number) {
    this.name = name;
    this.x = x;
    this.y = y;
  }

  update(deltaMs: number): void {
    // base update logic — runs every frame
    console.log(`${this.name} updating...`);
  }
}

class Enemy extends Actor {
  health: number;

  constructor(name: string, x: number, y: number, health: number) {
    super(name, x, y); // must come before any reference to `this`
    this.health = health;
  }
}

const goblin = new Enemy("Goblin", 100, 200, 30);
console.log(goblin.name);   // "Goblin"  — inherited from Actor
console.log(goblin.health); // 30        — defined on Enemy
ℹ
Note

Enemy automatically gains name, x, y, and update() without redeclaring them. Inheritance is additive: a subclass starts with everything the parent has, then layers on its own members.

Calling super() in the Constructor

When a subclass defines its own constructor, the very first statement must be super(...). This hands the parent constructor the arguments it needs to initialize its own properties. TypeScript enforces this at compile time. 

class Slime extends Actor {
  color: string;

  constructor(x: number, y: number, color: string) {
    // TypeScript error if you access `this` before this line
    super("Slime", x, y);
    this.color = color;
  }
}
⚠
Warning

Accessing this before super() is a runtime error in JavaScript and a compile error in TypeScript. TypeScript will flag it with: "'super' must be called before accessing 'this' in the constructor of a derived class." Always put super() first.

The protected Access Modifier

By default, class members are public. A private member is invisible everywhere outside the declaring class, including subclasses. That's often too strict for base classes that are designed to be extended. The protected modifier is the middle ground: visible inside the class and all subclasses, but not to outside callers. 

class Actor {
  name: string;
  protected hp: number; // subclasses can read and write this

  constructor(name: string, hp: number) {
    this.name = name;
    this.hp = hp;
  }
}

class Boss extends Actor {
  takeDamage(amount: number): void {
    this.hp -= amount; // OK: hp is protected, Boss is a subclass
    if (this.hp <= 0) {
      console.log(`${this.name} has been defeated!`);
    }
  }
}

const boss = new Boss("Dragon", 500);
boss.takeDamage(100); // fine
// boss.hp -= 50;     // Error: 'hp' is protected
💡
Tip

Reach for protected when you are writing a base class that other developers (or your future self) will extend. It communicates intent: "this member is an implementation detail, not a public API, but subclasses are expected to work with it."

Overriding Methods

A subclass can replace a parent method with its own version. TypeScript requires the override keyword (when noImplicitOverride is enabled) to make the intent explicit and catch typos that would silently create a new method instead of replacing the parent's. 

class Actor {
  name: string;

  constructor(name: string) {
    this.name = name;
  }

  update(deltaMs: number): void {
    // base: do nothing by default
  }
}

class Patrol extends Actor {
  private direction: number = 1;

  override update(deltaMs: number): void {
    // custom patrol logic replaces the base update entirely
    this.direction *= -1;
    console.log(`${this.name} turns and walks the other way`);
  }
}
📌
Remember

The overriding method's signature must be compatible with the parent's. You can widen return types and narrow parameter types, but you cannot change the parameter count in a way that breaks callers who hold a reference typed as the base class.

Calling super.method() From an Override

Overriding replaces the parent's logic entirely. When you still want the parent's behavior and want to add to it rather than replace it, call super.methodName() from inside the override. 

class Actor {
  name: string;

  constructor(name: string) {
    this.name = name;
  }

  update(deltaMs: number): void {
    // base update: could handle timers, status effects, etc.
    console.log(`[base] ${this.name} base update`);
  }
}

class FlickeringEnemy extends Actor {
  private flashTimer: number = 0;

  override update(deltaMs: number): void {
    super.update(deltaMs); // run parent logic first
    this.flashTimer += deltaMs;
    if (this.flashTimer > 500) {
      console.log(`${this.name} flickers!`);
      this.flashTimer = 0;
    }
  }
}
💡
Tip

Calling super.update() first is the conventional pattern in game engines (including Excalibur) because it lets the base class stabilize state before your subclass logic reads it. In UI frameworks the order is sometimes reversed for lifecycle reasons, so always check the framework's docs.

Putting It Together: An Excalibur Enemy Hierarchy

Here is a realistic hierarchy you would build in an Excalibur game. The base BaseEnemy class handles health, damage, and death. Subclasses extend it to add specialized behavior without duplicating any shared code. 

import { Actor, Engine, vec } from "excalibur";

// Base class: shared behavior for all enemies
class BaseEnemy extends Actor {
  protected hp: number;
  protected maxHp: number;

  constructor(name: string, x: number, y: number, hp: number) {
    super({ name, pos: vec(x, y) });
    this.hp = hp;
    this.maxHp = hp;
  }

  takeDamage(amount: number): void {
    this.hp = Math.max(0, this.hp - amount);
    console.log(`${this.name} has ${this.hp}/${this.maxHp} HP`);
    if (this.hp === 0) {
      this.onDeath();
    }
  }

  protected onDeath(): void {
    console.log(`${this.name} was defeated`);
    this.kill();
  }
}

// Subclass: a fast enemy that flees when low on health
class ScoutEnemy extends BaseEnemy {
  private speed: number;

  constructor(x: number, y: number) {
    super("Scout", x, y, 20);
    this.speed = 200;
  }

  override onUpdate(engine: Engine, deltaMs: number): void {
    if (this.hp < this.maxHp * 0.25) {
      // flee upward when below 25% health
      this.vel = vec(0, -this.speed);
    }
  }
}

// Subclass: a heavy enemy that explodes on death
class TankEnemy extends BaseEnemy {
  constructor(x: number, y: number) {
    super("Tank", x, y, 100);
  }

  protected override onDeath(): void {
    console.log(`${this.name} EXPLODES!`);
    // spawn explosion actor here in a real game
    super.onDeath(); // still call kill() via parent
  }
}
ℹ
Note

onDeath() is marked protected on BaseEnemy so subclasses can override it, but outside code cannot call it directly. This is the pattern Excalibur itself uses for lifecycle hooks like onInitialize and onPreUpdate.

Summary
  • Use extends to create a subclass that inherits all public and protected members from its parent class.
  • super() must be the first statement in a subclass constructor; it forwards arguments to the parent's constructor and initializes inherited properties before this becomes available.
  • Mark base class members protected when subclasses need to access them directly, but outside callers should not.
  • Use the override keyword to replace a parent method; TypeScript will error if the method does not exist on the parent, catching silent typos.
  • Call super.methodName() inside an override to run the parent's logic alongside the subclass's additions rather than replacing it entirely.
  • Excalibur's actor lifecycle hooks (onInitialize, onPreUpdate, onPostUpdate) are designed to be overridden, making inheritance a natural fit for building typed enemy and projectile hierarchies.

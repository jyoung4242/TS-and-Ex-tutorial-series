Introduction

Every enemy you spawn in a game is its own object: its own position, its own health, its own state. But some things belong to all enemies at once. How many are currently alive? What is the maximum number allowed on screen? That kind of information does not live on any single instance. It lives on the class itself, and that is exactly what static is for.

In TypeScript, the static keyword lets you attach properties and methods directly to the class rather than to objects created from it. You have already worked with instance members, which exist on each new object. Static members exist once, on the class, and are shared by everyone who references it.

This distinction sounds subtle but has a big practical impact. Understanding it unlocks patterns like shared counters, factory helpers, global registries, and configuration constants, all of which appear constantly in game development.

Instance Members vs. Static Members

When you write a class property or method without static, every object you create gets its own copy. Change the value on one object, and nothing happens to any other object. 


class Enemy {
  health: number;

  constructor(health: number) {
    this.health = health;
  }

  takeDamage(amount: number): void {
    this.health -= amount;
  }
}

const goblin = new Enemy(30);
const orc    = new Enemy(80);

goblin.takeDamage(10);

console.log(goblin.health); // 20
console.log(orc.health);    // 80 — completely independent

Now add a static property to track how many enemies have ever been created:


class Enemy {
  static count: number = 0;   // lives on the class, not on each object
  health: number;

  constructor(health: number) {
    this.health = health;
    Enemy.count++;            // increment via the class name, not `this`
  }
}

const goblin = new Enemy(30);
const orc    = new Enemy(80);

console.log(Enemy.count); // 2
// goblin.count  — TypeScript error: Property 'count' does not exist on type 'Enemy'
ℹ
Note

You access a static member through the class name (Enemy.count), not through an instance (goblin.count). TypeScript enforces this at compile time, so mistakes are caught before you run the code.

Static Methods

Methods can be static too. A static method is a function that belongs to the class itself. It cannot access instance properties via this because it is not called on an instance. 


class Enemy {
  static count: number = 0;
  static maxAllowed: number = 10;

  health: number;
  name: string;

  constructor(name: string, health: number) {
    this.name   = name;
    this.health = health;
    Enemy.count++;
  }

  // Static factory method: creates an enemy only if room exists
  static createIfAllowed(name: string, health: number): Enemy | null {
    if (Enemy.count >= Enemy.maxAllowed) {
      console.warn("Enemy cap reached!");
      return null;
    }
    return new Enemy(name, health);
  }

  // Static utility: resets the counter (e.g., on level change)
  static reset(): void {
    Enemy.count = 0;
  }
}

const goblin = Enemy.createIfAllowed("Goblin", 30);
console.log(Enemy.count); // 1

Enemy.reset();
console.log(Enemy.count); // 0
⚠
Warning

Inside a static method, this refers to the class itself, not to any instance. If you try to read this.health inside a static method, TypeScript will give you a type error. Use the class name directly: Enemy.count.

Static vs. Instance: Choosing the Right Tool

Use this quick mental test:

  • Does each object need its own copy of this value? Instance member.
  • Is this value shared across all objects, or does it describe the class itself? Static member.

class Bullet {
  // Each bullet has its own position — instance property
  x: number;
  y: number;

  // All bullets share the same speed cap — static constant
  static readonly MAX_SPEED: number = 800;

  constructor(x: number, y: number) {
    this.x = x;
    this.y = y;
  }
}

console.log(Bullet.MAX_SPEED); // 800
💡
Tip

Pair static with readonly for constants. TypeScript will then prevent any code from accidentally reassigning the value after it is set.

Static Members and Inheritance

Subclasses inherit static members from their parent class, but each subclass maintains its own copy of any static property it redeclares. 


class Actor {
  static category: string = "generic";
}

class Player extends Actor {
  static category: string = "player";  // shadows the parent's static
}

class Enemy extends Actor {
  // does NOT redeclare category, so it inherits from Actor
}

console.log(Actor.category);  // "generic"
console.log(Player.category); // "player"
console.log(Enemy.category);  // "generic"  (inherited)
📌
Remember

Inherited statics are accessed through either the parent or the child class name. Redeclaring a static on the subclass creates a separate property specific to that subclass, leaving the parent's value unchanged.

  2. Add a static readonly MAX_BULLETS: number = 20 constant.

Summary
  • The static keyword places a property or method on the class itself, not on any instance, so it is shared across all uses of that class.
  • Static members are accessed via the class name (Enemy.count), never via this or an instance variable.
  • Use static properties for shared state such as counters, caps, and configuration constants; use instance properties for data that belongs to individual objects.
  • Static methods cannot read instance properties directly; they operate only on other static members or on arguments passed in.
  • Combining static with readonly creates a compile-time constant that TypeScript will prevent from being overwritten.
  • Subclasses inherit static members from their parent but can shadow them by redeclaring the static with the same name.

Introduction

Arrays are everywhere in game development. Enemy lists, projectile pools, score histories, queued sound effects — virtually every system in a game engine manages collections of things. In plain JavaScript those collections are completely unguarded: you can push a string into an array that was supposed to hold enemies and JavaScript will not complain until something explodes at runtime.

TypeScript fixes this at the type level. By annotating an array with a specific element type, the compiler enforces what goes in and what comes out. That means mistakes like mixing up a health value with a damage multiplier get caught before a single frame is rendered, not during a playtest session.

This lesson covers the two ways to declare typed arrays, how TypeScript infers element types from initialized values, and the important gotcha that arises when you start with an empty array. Every example uses game-relevant data so the patterns map directly to real Excalibur code.

Declaring Typed Arrays

TypeScript gives you two syntactically equivalent ways to declare an array type. Both are valid and you will see both in the wild, so it is worth knowing them equally. 

// Syntax 1: shorthand — most common in practice
const enemyNames: string[] = ["Slime", "Goblin", "Wraith"];

// Syntax 2: generic — identical meaning, preferred in some team styles
const enemyNames: Array<string> = ["Slime", "Goblin", "Wraith"];
ℹ
Note

Both forms compile to the same JavaScript. Pick one style per codebase and stay consistent. The shorthand T[] is more common in TypeScript projects, while Array<T> appears more often when the element type itself is complex (like a union or generic type) and the shorthand would become hard to read.

With strict mode enabled, TypeScript will reject any operation that violates the declared element type. Attempting to insert the wrong type of value causes a compile error immediately. 

const spawnCounts: number[] = [3, 5, 12];

spawnCounts.push(7);       // OK
spawnCounts.push("seven"); // Error: Argument of type 'string' is not assignable
                            //        to parameter of type 'number'.

Type Inference on Initialized Arrays

When you initialize an array with values, TypeScript infers the element type automatically. You do not have to write the annotation at all if the initial values make the type unambiguous. 

// TypeScript infers: number[]
const waveSizes = [4, 8, 16, 32];

// TypeScript infers: string[]
const levels = ["forest", "dungeon", "volcano", "sky-temple"];

// TypeScript infers: boolean[]
const bossDefeated = [false, false, false];
💡
Tip

Hover over an array variable in your editor. The inferred type appears in the tooltip. If you see something unexpected, like (string | number)[] when you wanted number[], it means the initial values contain mixed types. Add an explicit annotation to lock it down.

The Empty Array Trap

This is the most common TypeScript array mistake. When you declare an array with no initial values and no annotation, TypeScript infers its type as never[]. That means nothing can ever be pushed into it, which is almost certainly not what you intended. 

// BAD — TypeScript infers never[]
const projectiles = [];

projectiles.push({ x: 100, y: 200, speed: 5 });
// Error: Argument of type '{ x: number; y: number; speed: number; }'
//        is not assignable to parameter of type 'never'.

The fix is simple: provide an explicit type annotation whenever you initialize an empty array.

// GOOD — explicitly typed, safe to push into
interface Projectile {
  x: number;
  y: number;
  speed: number;
}

const projectiles: Projectile[] = [];

projectiles.push({ x: 100, y: 200, speed: 5 }); // OK
⚠
Warning

In game engines like Excalibur you will often create empty pools at startup and populate them later (enemy pools, particle lists, active projectiles). Every one of those empty arrays needs an explicit type annotation or you will hit never[] errors the first time you try to add an element.

Arrays of Objects and Game Entities

Most real game data is not a primitive array. You will work with arrays of structured objects representing enemies, items, waypoints, and events. Typing these works the same way: define an interface or type alias, then use it as the element type. 

interface Enemy {
  id: number;
  name: string;
  health: number;
  isAlive: boolean;
}

const enemies: Enemy[] = [
  { id: 1, name: "Slime",  health: 30,  isAlive: true },
  { id: 2, name: "Goblin", health: 60,  isAlive: true },
  { id: 3, name: "Wraith", health: 120, isAlive: false },
];

// TypeScript knows each element is an Enemy
// so accessing .health is safe and autocompleted
const totalHealth = enemies.reduce((sum, e) => sum + e.health, 0);

Try It: Excalibur Playground

The snippet below models a simple enemy wave system using typed arrays. A WaveEnemy interface defines the shape of each entry. The active enemies array is filtered down to living targets before the wave-clear check runs. Modify the health values or add new enemies and watch TypeScript enforce the shape at every step. 

import * as ex from "excalibur";

interface WaveEnemy {
  actor: ex.Actor;
  health: number;
  isAlive: boolean;
}

// Typed empty array — safe to push into
const waveEnemies: WaveEnemy[] = [];

function spawnWave(engine: ex.Engine): void {
  const positions: ex.Vector[] = [
    ex.vec(100, 100),
    ex.vec(300, 100),
    ex.vec(500, 100),
  ];

  for (const pos of positions) {
    const actor = new ex.Actor({
      pos,
      width: 32,
      height: 32,
      color: ex.Color.Red,
    });

    engine.add(actor);

    waveEnemies.push({
      actor,
      health: 30,
      isAlive: true,
    });
  }
}

function dealDamage(target: WaveEnemy, amount: number): void {
  target.health -= amount;
  if (target.health <= 0) {
    target.isAlive = false;
    target.actor.kill();
  }
}

function isWaveCleared(): boolean {
  const livingEnemies: WaveEnemy[] = waveEnemies.filter(e => e.isAlive);
  return livingEnemies.length === 0;
}

Summary
  • Typed arrays are declared with T[] or Array<T> — both forms are equivalent and interchangeable.
  • TypeScript infers element types from initialized values, but empty arrays without an annotation become never[] and must be explicitly typed.
  • Arrays of objects follow the same rules: define an interface or type alias for the element shape, then use it as the array's element type.

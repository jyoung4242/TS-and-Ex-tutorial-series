Introduction

Picture a game where you define a fixed list of valid spawn points on a map. You pass that list to a dozen different systems: the renderer, the collision detector, the enemy AI. If any one of those systems accidentally pushes a new point onto the array, or sorts it in place, every other system silently sees corrupted data. The bug will be hard to trace and unpredictable in its effects.

TypeScript gives you a way to prevent this class of bug entirely at compile time: readonly arrays. By marking an array as readonly, you tell both TypeScript and your future self that this data is meant to be observed, not modified. No push. No pop. No splice. The compiler enforces the contract.

In this lesson you will learn how readonly arrays work, how they relate to the broader concept of immutability in TypeScript, and how to apply them confidently in function signatures and game data structures.

Declaring a Readonly Array

There are two equivalent syntaxes for a readonly array. Both mean exactly the same thing to the TypeScript compiler — choose whichever reads more clearly in context. 


// Syntax 1: readonly modifier before the element type
const spawnPoints: readonly [number, number][] = [
  [100, 200],
  [400, 150],
  [700, 300],
];

// Syntax 2: ReadonlyArray generic
const spawnPoints2: ReadonlyArray<[number, number]> = [
  [100, 200],
  [400, 150],
  [700, 300],
];

With either syntax, TypeScript will now reject any call that would mutate the array:


spawnPoints.push([50, 80]);   // Error: Property 'push' does not exist on type 'readonly'
spawnPoints.pop();            // Error: Property 'pop' does not exist on type 'readonly'
spawnPoints[0] = [0, 0];     // Error: Index signature in type 'readonly' only permits reading

Read operations are completely unaffected. You can still iterate, map, filter, and index as normal.


// All of these are fine
const first = spawnPoints[0];
const count = spawnPoints.length;
const mapped = spawnPoints.map(([x, y]) => ({ x, y }));
for (const point of spawnPoints) {
  console.log(point);
}
ℹ
Note

Readonly arrays still have access to all non-mutating array methods: map, filter, find, reduce, forEach, slice, and more. The restriction only applies to methods that change the array in place.

Readonly in Function Parameters

The most important place to use readonly arrays is in function signatures. When a function accepts a readonly array, you are making a promise to callers: "I will not modify your data." This lets callers pass in their own mutable arrays without fear. 


// This function promises not to mutate the array it receives
function getClosestSpawn(
  playerX: number,
  playerY: number,
  spawns: readonly [number, number][]
): [number, number] {
  return spawns.reduce((best, point) => {
    const distBest = Math.hypot(best[0] - playerX, best[1] - playerY);
    const distPoint = Math.hypot(point[0] - playerX, point[1] - playerY);
    return distPoint < distBest ? point : best;
  });
}

// A mutable array can be passed to a readonly parameter — this is always safe
const mutableSpawns: [number, number][] = [[100, 200], [400, 150]];
const closest = getClosestSpawn(300, 300, mutableSpawns);
💡
Tip

As a general rule: if a function only reads from an array parameter, declare it as readonly. This widens what callers can pass in and makes the function's intent explicit. It costs nothing at runtime.

The direction of assignability is worth understanding clearly. A mutable array is assignable to a readonly parameter, but the reverse is not true without an explicit assertion. 


const readonlyNums: readonly number[] = [1, 2, 3];
const mutableNums: number[] = [1, 2, 3];

// OK: mutable -> readonly (safe — you are adding a restriction)
function logAll(items: readonly number[]) { /* ... */ }
logAll(mutableNums);

// Error: readonly -> mutable (unsafe — you would be removing a restriction)
function sortInPlace(items: number[]) { items.sort(); }
sortInPlace(readonlyNums); // Error: Argument of type 'readonly number[]' is not assignable
📌
Remember

Mutable arrays can flow into readonly parameters. Readonly arrays cannot flow into mutable parameters. The readonly modifier is a narrowing of what operations are permitted, not a different kind of array.

Compile-Time vs. Runtime Immutability

TypeScript's readonly is a compile-time constraint only. It disappears completely after transpilation. The underlying JavaScript array is still a plain array object and nothing prevents mutation at runtime if you bypass the type system. 


const scores: readonly number[] = [10, 20, 30];

// TypeScript will catch this:
// scores.push(40); // Error

// But this bypasses the type checker entirely:
(scores as number[]).push(40);
console.log(scores); // [10, 20, 30, 40] — mutated at runtime!
⚠
Warning

Using as to cast away readonly is a code smell. It silences the compiler without fixing the underlying design. If you find yourself doing this, reconsider whether the data should be mutable in the first place.

If you need true runtime immutability, use Object.freeze(). This prevents mutation even in plain JavaScript, but it only freezes one level deep. 


const frozenScores = Object.freeze([10, 20, 30]);
frozenScores.push(40); // Throws TypeError in strict mode at runtime

In practice, for most game data structures, compile-time immutability is sufficient. The goal is to catch accidental mutations during development, not to guard against deliberate runtime attacks.

Deep Immutability with as const

The as const assertion is a powerful shorthand that turns any literal value into its narrowest possible readonly type. For arrays, every element becomes its literal type and the array itself becomes readonly. 


// Without as const: inferred as string[]
const directions = ["up", "down", "left", "right"];

// With as const: inferred as readonly ["up", "down", "left", "right"]
const directions2 = ["up", "down", "left", "right"] as const;

// You can now use the type as a union
type Direction = typeof directions2[number];
// type Direction = "up" | "down" | "left" | "right"

function move(dir: Direction) {
  console.log(`Moving ${dir}`);
}

move("up");    // OK
move("diagonal"); // Error: Argument of type '"diagonal"' is not assignable

This pattern is especially useful for defining game configuration data that doubles as a source of truth for a union type.


const ACTOR_TAGS = ["player", "enemy", "projectile", "pickup"] as const;
type ActorTag = typeof ACTOR_TAGS[number];

function tagActor(tag: ActorTag) {
  // TypeScript knows exactly which strings are valid
  console.log(`Tagging actor as: ${tag}`);
}

tagActor("player");     // OK
tagActor("obstacle");   // Error at compile time
💡
Tip

The typeof Array[number] pattern is a clean way to derive a union type from an as const array. It keeps your union and your list in sync automatically: add a value to the array and the union updates for free.

Readonly Tuples

Tuples are fixed-length arrays where each position has a specific type. You can make them readonly the same way as regular arrays. 


// A mutable tuple
type Point2D = [number, number];

// A readonly tuple
type ReadonlyPoint2D = readonly [number, number];

function reflectX(point: ReadonlyPoint2D): ReadonlyPoint2D {
  return [-point[0], point[1]];
}

const origin: ReadonlyPoint2D = [0, 0];
const reflected = reflectX([3, 4]); // [−3, 4]

// Can't mutate
origin[0] = 5; // Error: Cannot assign to '0' because it is a read-only property

Readonly tuples are a good fit for representing immutable geometric data like positions, sizes, or color channels where the structure is fixed and mutation would be a bug.

Summary
  • Use readonly T[] or ReadonlyArray<T> to declare arrays that cannot be mutated through that reference.
  • Mutable arrays are assignable to readonly parameters, but readonly arrays cannot be passed to mutable parameters.
  • TypeScript's readonly is a compile-time check only. It does not prevent runtime mutation if you cast the type away.
  • The as const assertion creates a deeply readonly literal type, narrowing each value to its exact type.
  • The typeof Array[number] pattern derives a union type from an as const array, keeping your type and data in sync.
  • Prefer readonly parameters for any function that only reads from an array. It makes intent clear and widens what callers can safely pass in.

Introduction

Imagine you have an array of enemy definitions for your game. Each enemy object has a name, health, and speed. Now you need a second type where every property on that same object is optional, so players can partially override enemy stats. Do you copy the type and add ? to every field by hand? What happens when you add a new field and forget to update the copy?

Mapped types solve this. They let TypeScript derive a new type by walking over the keys of an existing type and applying a transformation to each one. Instead of duplicating structure, you describe the transformation once, and TypeScript keeps everything in sync for you.

In this lesson you will learn how mapped types work, how to combine them with array element types to transform collections, and how that pattern shows up naturally when building game systems with ExcaliburJS.

What Is a Mapped Type?

A mapped type is a type that iterates over a set of keys and produces a new object type. The basic syntax looks like a for...in loop written inside a type definition. 


// A simple mapped type that makes every property optional
type Partial<T> = {
  [K in keyof T]?: T[K];
};

Breaking that down:

  • [K in keyof T] iterates over every key of T, binding each key to K.
  • ? makes the resulting property optional.
  • T[K] looks up the type of each property on T (an indexed access type).
ℹ
Note

Partial<T>, Required<T>, and Readonly<T> are all built into TypeScript's standard library as mapped types. You get them for free without any import.

Mapping Over a Concrete Type

Here is a concrete game example. Suppose you have an EnemyStats type and you want to create a PartialEnemyStats type where every field is optional for patching purposes. 


type EnemyStats = {
  name: string;
  health: number;
  speed: number;
  damage: number;
};

// Derived automatically — no manual copy needed
type PartialEnemyStats = {
  [K in keyof EnemyStats]?: EnemyStats[K];
};

// This is exactly the same as writing:
// { name?: string; health?: number; speed?: number; damage?: number; }

If you later add armor: number to EnemyStats, PartialEnemyStats gets armor?: number automatically. Nothing breaks, nothing drifts.

💡
Tip

In practice you would just write Partial<EnemyStats> directly. Writing the expansion out by hand here is only to show you what the built-in utility type is doing under the hood.

Array Element Types and Mapped Types

Mapped types operate on object keys, but your data often lives inside arrays. To bridge the gap, TypeScript gives you T[number]: a way to extract the element type of any array type. 


type EnemyDefinition = {
  id: string;
  name: string;
  health: number;
  speed: number;
};

type EnemyList = EnemyDefinition[];

// Extract the element type from the array type
type SingleEnemy = EnemyList[number];
// SingleEnemy is now exactly: EnemyDefinition

T[number] works because arrays are indexed by numbers. TypeScript uses that index to look up the element type, the same way T[K] looks up a property type by key name.

📌
Remember

Array<T>[number] and T[][number] both return T. Use whichever form matches your existing type declaration.

Combining the Two: Map Over an Array's Element Type

Now for the powerful part. You can chain T[number] with a mapped type to transform every property of an array's element type at once. 


type EnemyDefinition = {
  id: string;
  name: string;
  health: number;
  speed: number;
};

// Step 1: get the element type
type EnemyElement = EnemyDefinition[][number]; // EnemyDefinition

// Step 2: map over its keys to make every value a string (for a display layer)
type DisplayEnemy = {
  [K in keyof EnemyElement]: string;
};
// { id: string; name: string; health: string; speed: string; }

The pattern is always the same: extract the element type first with [number], then map over its keys. You can apply any transformation in the mapped type body.

⚠
Warning

T[number] only makes sense on array types. Using it on a plain object type produces a union of all its value types, which is rarely what you want. Always double-check that T is an array before indexing with number.

A Practical Game Pattern: Typed Configuration Patches

A common game-dev scenario is having a fixed array of level configurations defined at startup, then allowing runtime overrides for individual fields without replacing the whole object. Mapped types make the override type trivial to derive. 


// Defined once — the authoritative shape
const levelConfigs = [
  { id: "level-1", title: "Forest Run", gravity: 800, enemyCount: 5 },
  { id: "level-2", title: "Ice Cave",   gravity: 600, enemyCount: 8 },
] as const;

// Derive the element type from the runtime array
type LevelConfig = typeof levelConfigs[number];
// { readonly id: string; readonly title: string; readonly gravity: number; readonly enemyCount: number; }

// Derive a patch type — every property becomes optional
type LevelPatch = {
  [K in keyof LevelConfig]?: LevelConfig[K];
};

// Usage: merge a patch over a config at runtime
function applyPatch(base: LevelConfig, patch: LevelPatch): LevelConfig {
  return { ...base, ...patch };
}

const override = applyPatch(levelConfigs[0], { gravity: 300 });
// TypeScript ensures 'gravity' is a number — no raw object spreading allowed
ℹ
Note

typeof levelConfigs[number] is the idiomatic way to pull an element type out of a value (an actual variable) rather than from a named type. typeof first converts the value to its type, then [number] extracts the element type.

Adding Modifiers: Readonly and Required

Mapped types support two modifiers that can be applied or removed with + and -. This lets you lock down or loosen properties as part of the transformation. 


type EnemyDefinition = {
  id: string;
  name?: string;  // optional on the source
  health: number;
};

// Remove optionality and make everything readonly
type FrozenEnemy = {
  +readonly [K in keyof EnemyDefinition]-?: EnemyDefinition[K];
};
// { readonly id: string; readonly name: string; readonly health: number; }

// Note: -? strips the optional marker, making all properties required
// Note: +readonly (or just readonly) adds the readonly modifier
💡
Tip

-? is the modifier behind the built-in Required<T> utility type. You can combine modifiers freely in your own mapped types when none of the built-ins fit exactly.

Summary
  • A mapped type iterates over a set of keys with [K in keyof T] and produces a new object type with a transformation applied to each property.
  • T[number] extracts the element type from an array type, giving you a single object type you can then map over.
  • Combining typeof myArray[number] with a mapped type lets you derive new types directly from runtime array values without duplicating type definitions.
  • The +readonly and -? modifiers (and their inverses) let you add or remove readonly and optional markers as part of the mapping.
  • Built-in utility types like Partial, Required, and Readonly are ordinary mapped types — understanding the pattern lets you write your own when the built-ins do not fit.

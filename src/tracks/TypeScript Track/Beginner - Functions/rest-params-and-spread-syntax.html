Introduction

Imagine you are writing a function that damages several enemies at once after an explosion. You do not know ahead of time how many enemies are caught in the blast radius. You could accept an array, but that forces every call site to wrap its arguments in brackets. Or you could write a dozen overloads. Neither feels right.

Rest parameters solve this cleanly. They let a function accept any number of individual arguments and collect them into a typed array automatically. The companion feature, the spread operator, goes in the other direction: it unpacks an existing array so each element is passed as its own argument. Together they cover the full round-trip between discrete values and collections, and TypeScript types both sides precisely.

In Excalibur, you will see this pattern constantly: engine event systems forward variable argument lists, actor constructors accept spread config properties, and utility helpers merge component arrays. Understanding rest and spread at the type level makes those APIs feel natural rather than mysterious.

Rest Parameters

A rest parameter is written as the final parameter of a function, prefixed with .... TypeScript types it as an array of whatever element type you declare. 

// Without rest — callers must build an array manually
function damageEnemies(enemies: string[]): void {
  for (const enemy of enemies) {
    console.log(`${enemy} takes damage!`);
  }
}

damageEnemies(["Goblin", "Orc", "Troll"]); // array literal required


// With rest — each enemy is a separate argument
function damageEnemiesRest(...enemies: string[]): void {
  for (const enemy of enemies) {
    console.log(`${enemy} takes damage!`);
  }
}

damageEnemiesRest("Goblin", "Orc", "Troll"); // natural call site
damageEnemiesRest("Boss");                   // one argument also works
damageEnemiesRest();                         // zero arguments also works
ℹ
Note

TypeScript infers the rest parameter type as string[] here. Inside the function body, enemies is a perfectly ordinary array — you can call .map, .filter, or any other array method on it.

Rest Must Come Last

A rest parameter collects everything from its position onward, so it must be the final parameter in the list. TypeScript enforces this at compile time. 

// Correct: required parameters come first, rest comes last
function spawnWave(
  waveName: string,
  difficulty: number,
  ...enemyTypes: string[]
): void {
  console.log(`Wave: ${waveName} | Difficulty: ${difficulty}`);
  enemyTypes.forEach(type => console.log(`  Spawning: ${type}`));
}

spawnWave("Midnight Raid", 3, "Skeleton", "Zombie", "Wraith");

// TypeScript error — rest is not last
// function broken(...names: string[], count: number) {} // TS2014
⚠
Warning

A function can only have one rest parameter, and it must be the very last parameter. Trying to add a required parameter after a rest parameter is a TypeScript error (TS2014).

Typing Rest Parameters with Union Types

The element type of a rest parameter can be any valid TypeScript type, including unions. This is useful when your game engine needs to accept mixed payloads. 

type GameEvent = "spawn" | "destroy" | "pause" | "resume";

function broadcastEvents(...events: GameEvent[]): void {
  events.forEach(event => {
    console.log(`Broadcasting: ${event}`);
  });
}

broadcastEvents("spawn", "pause");           // valid
broadcastEvents("destroy", "resume", "spawn"); // valid

// TypeScript error — "reload" is not a GameEvent
// broadcastEvents("spawn", "reload");       // TS2345
💡
Tip

Typing the rest parameter with a string union instead of plain string turns every call site into a compile-time check. Mistyped event names become errors before you ever run the game.

The Spread Operator

The spread operator (...) unpacks an iterable, such as an array, into individual elements at a call site. It is the natural counterpart to a rest parameter. 

function applyBuffs(actor: string, ...buffs: string[]): void {
  console.log(`${actor} gains: ${buffs.join(", ")}`);
}

const heroeBuffs: string[] = ["Haste", "Shield", "Regeneration"];

// Without spread — TypeScript error because applyBuffs expects separate args
// applyBuffs("Hero", heroeBuffs); // TS2345

// With spread — array is unpacked into individual arguments
applyBuffs("Hero", ...heroeBuffs);
// Output: Hero gains: Haste, Shield, Regeneration
📌
Remember

Rest collects: it gathers individual arguments into an array inside the function. Spread expands: it unpacks an array into individual arguments at the call site. They are inverses of each other.

Spreading into Non-Rest Functions

You can spread an array into any function, not just ones with rest parameters, as long as the types align. TypeScript checks each spread element against the corresponding parameter. 

function createActor(x: number, y: number, label: string): string {
  return `Actor "${label}" at (${x}, ${y})`;
}

const position: [number, number, string] = [100, 200, "Player"];

// Spread a tuple directly into the function
console.log(createActor(...position));
// Output: Actor "Player" at (100, 200)
ℹ
Note

TypeScript can verify spread calls into fixed-parameter functions when the source is typed as a tuple (a fixed-length typed array like [number, number, string]). If the source is typed as a plain array like number[], TypeScript cannot guarantee the length matches, and you may see an error.

Spread with Arrays and Merge Patterns

Spread is also heavily used outside of function calls to build new arrays from existing ones. In a game, you might merge actor lists, combine effect queues, or extend config objects. 

const groundEnemies: string[] = ["Goblin", "Skeleton"];
const airEnemies: string[]   = ["Bat", "Harpy"];
const bossEnemies: string[]  = ["Dragon"];

// Merge into a new wave without mutating either source array
const fullWave: string[] = [...groundEnemies, ...airEnemies, ...bossEnemies];

console.log(fullWave);
// ["Goblin", "Skeleton", "Bat", "Harpy", "Dragon"]

// Spread also works for object literals (useful for Excalibur config merging)
const defaultConfig = { speed: 100, health: 50, visible: true };
const bossConfig    = { ...defaultConfig, health: 500, name: "Dragon" };

console.log(bossConfig);
// { speed: 100, health: 500, visible: true, name: "Dragon" }
💡
Tip

When spreading objects, later properties override earlier ones. In the example above, bossConfig.health is 500, not 50, because the second spread property wins. This makes spread a clean pattern for applying default values with targeted overrides.

Tuples, Rest, and Spread Together

TypeScript supports rest elements inside tuple types. This is an advanced but practical pattern when you want to describe a typed list that has a known prefix followed by a variable tail. 

// A tuple: first element is a string label, rest are numbers (scores)
type ScoredRound = [label: string, ...scores: number[]];

function summarizeRound(label: string, ...scores: number[]): string {
  const total = scores.reduce((sum, s) => sum + s, 0);
  return `${label}: ${scores.length} events, total score ${total}`;
}

const roundData: ScoredRound = ["Wave 3", 120, 85, 200, 60];

// Spread the tuple directly into the matching function signature
console.log(summarizeRound(...roundData));
// Output: Wave 3: 4 events, total score 465
⚠
Warning

If roundData were typed as (string | number)[] instead of the tuple ScoredRound, TypeScript would reject the spread into summarizeRound because it cannot confirm the first element is a string. Always use a tuple type when you need to spread a mixed array into a function with heterogeneous parameters.

Summary
  • Rest parameters (...name: T[]) allow a function to accept an indefinite number of arguments as an array, with the element type specified by the annotation.
  • The spread operator (...array) unpacks an array into individual arguments at a call site, and TypeScript verifies the types match the target function's parameters.
  • To spread a mixed array into a function with heterogeneous parameters, type the source as a tuple so TypeScript can confirm each positional type.
  • Spread works on both arrays and object literals; later properties override earlier ones when spreading objects, making it a clean pattern for applying defaults with overrides.
  • TypeScript's tuple rest element syntax ([T, ...U[]]) lets you describe and safely pass structured variadic data across API boundaries, such as Excalibur event payloads and scene initializers.

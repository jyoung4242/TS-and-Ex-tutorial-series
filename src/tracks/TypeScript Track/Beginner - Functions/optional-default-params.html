Introduction

Imagine you are writing a function that spawns an enemy in a game. Most of the time you want a standard enemy with 100 health and no special color tint. But sometimes you need a boss with 500 health and a red tint, or a fast scout with 50 health and no tint at all. If you forced callers to supply every single argument every time, the call sites would be noisy and error-prone.

TypeScript solves this with two complementary features: optional parameters, which the caller can simply omit, and default parameters, which fall back to a value you choose when nothing is passed. Together they let you write flexible, self-documenting functions without overloading or awkward undefined checks scattered everywhere.

In this lesson you will learn both features, understand the tradeoffs between them, and see them put to work in a small Excalibur playground.

Optional Parameters

Mark a parameter as optional by placing a ? immediately after its name, before the type annotation. TypeScript will then allow callers to omit that argument. Inside the function body, the parameter's type becomes a union with undefined, so you must handle both cases. 


// The second parameter is optional
function greetPlayer(name: string, title?: string): string {
  if (title) {
    return `Welcome, ${title} ${name}!`;
  }
  return `Welcome, ${name}!`;
}

greetPlayer("Ada");            // "Welcome, Ada!"
greetPlayer("Ada", "Captain"); // "Welcome, Captain Ada!"
ℹ
Note

When title is omitted, its value inside the function is undefined, not an empty string or zero. Always guard against that before using it.

The Ordering Rule

Optional parameters must come after all required parameters. Placing one before a required parameter is a TypeScript compile error, because there would be no unambiguous way to know which argument the caller intended to skip. 


// WRONG: optional before required
function badOrder(label?: string, value: number): void { /* ... */ }
//                                ^^^^^^ Error: Required parameter cannot follow optional

// CORRECT: required first, optional last
function goodOrder(value: number, label?: string): void {
  console.log(label ?? "unlabeled", value);
}
⚠
Warning

This ordering rule applies equally to optional parameters and default parameters. Both must trail all required parameters.

Default Parameters

A default parameter goes one step further: instead of becoming undefined when omitted, it takes on a value you specify at the function signature. Use = value after the type annotation (or after the parameter name when TypeScript can infer the type). 


function spawnEnemy(x: number, y: number, health: number = 100): void {
  console.log(`Spawning enemy at (${x}, ${y}) with ${health} HP`);
}

spawnEnemy(0, 0);         // health = 100  (default applied)
spawnEnemy(200, 300, 50); // health = 50   (caller overrides)

Notice that the type annotation for health is optional here because TypeScript infers number from the literal 100. You can include it explicitly for clarity, which is often a good idea in a codebase that values readability.

💡
Tip

Default parameter values can be any expression, not just literals. You can call a function, read a constant, or perform arithmetic: timeout: number = Date.now(). The expression is evaluated at call time, not at function definition time.

Passing undefined to Trigger a Default

You can explicitly pass undefined for a defaulted parameter to force the default to apply, even when supplying later arguments. This is especially useful when a parameter sits in the middle of a list. 


function createActor(
  name: string,
  health: number = 100,
  speed: number = 60
): string {
  return `${name} | HP: ${health} | SPD: ${speed}`;
}

// Skip health, set speed to 200
createActor("Scout", undefined, 200);
// "Scout | HP: 100 | SPD: 200"
📌
Remember

Passing undefined triggers the default. Passing null does not. null is a deliberate "no value" and will be assigned as-is, which can cause type errors if the parameter type does not include null.

Choosing Between Optional and Default

Both features let callers omit an argument, but they communicate different intentions and produce different types inside the function. 


// Optional: type is string | undefined inside the function
function labelA(text?: string): void {
  // text might be undefined here -- you must check
  const safe = text ?? "(none)";
  console.log(safe);
}

// Default: type is string inside the function (never undefined)
function labelB(text: string = "(none)"): void {
  // text is always a string -- no check needed
  console.log(text);
}

Use an optional parameter when the absence of the argument is meaningful and you want to handle the two cases differently. Use a default parameter when there is a sensible fallback value and you want the function body to work uniformly regardless of whether the caller supplied it.

💡
Tip

In practice, default parameters are more common because they keep the function body cleaner. Reach for optional parameters when you genuinely need to branch on whether the caller provided the argument at all.

Summary
  • Add ? after a parameter name to make it optional; its type becomes T | undefined inside the function body.
  • Use = value to give a parameter a default; the type remains T (never undefined), keeping the body simpler.
  • Both optional and default parameters must be declared after all required parameters, or TypeScript will report a compile error.
  • Passing undefined explicitly triggers a default; passing null does not.
  • Prefer default parameters when a sensible fallback exists; prefer optional parameters when the absence of an argument needs distinct handling.

Introduction

Imagine you are writing a helper function that creates a game sprite. When the caller passes a string, the function looks up the sprite by name and returns a Sprite. When the caller passes a SpriteConfig object, it builds a sprite from scratch and returns a AnimatedSprite. Both call the same function, but the return type depends on the input type. How do you express that to TypeScript?

A plain union type on the parameter (string | SpriteConfig) with a union return type (Sprite | AnimatedSprite) would compile, but it forces every caller to narrow the result themselves even when they already know which branch they took. Function overloads let you declare each valid input/output combination as its own signature, so TypeScript picks the exact return type for you at each call site.

In this lesson you will learn how to write overload signatures, how to satisfy them with a single implementation signature, and when to reach for this pattern versus simpler alternatives.

What Is a Function Overload?

A TypeScript function overload is a set of two or more overload signatures followed by one implementation signature. Only the overload signatures are visible to callers. The implementation signature is hidden; it exists purely to satisfy all the overloads at once. 


// Overload signature 1 — visible to callers
function createSprite(name: string): Sprite;

// Overload signature 2 — visible to callers
function createSprite(config: SpriteConfig): AnimatedSprite;

// Implementation signature — NOT visible to callers
function createSprite(nameOrConfig: string | SpriteConfig): Sprite | AnimatedSprite {
  if (typeof nameOrConfig === "string") {
    return lookupSprite(nameOrConfig);   // returns Sprite
  }
  return buildAnimatedSprite(nameOrConfig); // returns AnimatedSprite
}

When a caller writes createSprite("hero"), TypeScript matches the first overload and types the result as Sprite, with no extra narrowing required. When the caller writes createSprite({ frames: [...] }), TypeScript matches the second overload and types the result as AnimatedSprite.

ℹ
Note

TypeScript tries each overload signature in order and uses the first one that matches. Put the most specific signatures first to avoid unexpected matches.

Anatomy of an Overload

The Overload Signatures

Each overload signature looks like a normal function declaration but has no body. It describes one specific combination of parameter types and return type that you are promising to support. 


// Two overload signatures for a "move actor" utility
function moveActor(actor: Actor, x: number, y: number): void;
function moveActor(actor: Actor, position: Vector): void;

The Implementation Signature

The implementation signature must be compatible with all overload signatures above it. Its parameter types are usually union types, and its return type is the union of all overload return types. 


// Implementation — must handle both calling patterns
function moveActor(
  actor: Actor,
  xOrPosition: number | Vector,
  y?: number
): void {
  if (typeof xOrPosition === "number") {
    actor.pos = vec(xOrPosition, y!);
  } else {
    actor.pos = xOrPosition;
  }
}
⚠
Warning

The implementation signature is invisible to callers. If you call your own function with a combination of arguments that only matches the implementation signature but not any overload signature, TypeScript will reject it. Every valid call pattern must have a matching overload signature.

Narrowing Inside the Implementation

Inside the implementation body you work with the broad union types, so you must narrow them before using them. Standard narrowing techniques all work: typeof, instanceof, and type guard functions. 


type SpawnOptions =
  | { kind: "enemy"; health: number }
  | { kind: "pickup"; value: number };

function spawnActor(label: string): Actor;
function spawnActor(options: SpawnOptions): Actor;
function spawnActor(labelOrOptions: string | SpawnOptions): Actor {
  // Narrow with typeof
  if (typeof labelOrOptions === "string") {
    return new Actor({ name: labelOrOptions });
  }

  // Narrow with a discriminant property
  if (labelOrOptions.kind === "enemy") {
    return new EnemyActor({ health: labelOrOptions.health });
  }

  return new PickupActor({ value: labelOrOptions.value });
}
💡
Tip

Discriminated unions (objects that share a literal kind or type property) pair especially well with overloads. Each overload maps to one variant, and narrowing by the discriminant inside the implementation is clean and exhaustive.

Overloads on Class Methods

Overloads work on class methods too. The syntax is identical; just omit the function keyword and place the signatures inside the class body. 


class Scene {
  // Overload 1: add by Actor instance
  add(actor: Actor): void;
  // Overload 2: add by config object, receive back the created Actor
  add(config: ActorConfig): Actor;

  // Implementation
  add(actorOrConfig: Actor | ActorConfig): void | Actor {
    if (actorOrConfig instanceof Actor) {
      this.actors.push(actorOrConfig);
      return;
    }
    const actor = new Actor(actorOrConfig);
    this.actors.push(actor);
    return actor;
  }

  private actors: Actor[] = [];
}
📌
Remember

Every overload signature must be immediately adjacent to the implementation signature with no other statements in between. Inserting code between them is a syntax error.

When to Use Overloads (and When Not To)

Overloads solve a specific problem: the return type (or behavior) changes depending on the type of the input. Before reaching for them, consider whether a simpler approach covers your needs. 


// SIMPLE CASE — a union parameter with one return type
// No overload needed; union parameter is fine.
function setVolume(value: number | "mute"): void {
  // ...
}

// OVERLOAD CASE — return type changes with input type
// Without overloads every caller must narrow the result.
function getAsset(id: number): ImageSource;
function getAsset(id: string): SoundSource;
function getAsset(id: number | string): ImageSource | SoundSource {
  return typeof id === "number"
    ? imageAssets.get(id)!
    : soundAssets.get(id)!;
}

// Caller gets a precise type — no cast, no narrowing
const img = getAsset(42);   // ImageSource
const snd = getAsset("bgm"); // SoundSource
ℹ
Note

If every overload has the same return type, a union parameter is almost always cleaner. Overloads add indirection, so only add them when the precision they provide is actually useful to callers.

Summary
  • Function overloads let you declare multiple call signatures for a single function so callers receive a precise return type based on the arguments they pass.
  • You write two or more overload signatures (no body) followed by one implementation signature that handles all cases using union types.
  • The implementation signature is hidden from callers; every valid call pattern must be covered by an explicit overload signature.
  • Inside the implementation body, narrow union-typed parameters with typeof, instanceof, or discriminant properties before using them.
  • Prefer a simple union parameter when the return type does not change. Reach for overloads only when callers benefit from a more precise return type.

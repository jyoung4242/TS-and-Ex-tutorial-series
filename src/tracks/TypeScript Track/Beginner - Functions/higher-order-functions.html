Introduction

Imagine you are writing an enemy spawner. At the moment an enemy is destroyed you want to play a sound, update the score, and maybe spawn a power-up. Those three actions are different every time you call the spawner, but the spawner itself never changes. The answer is to pass behavior in as a parameter, which is exactly what higher-order functions let you do.

A higher-order function is any function that either accepts another function as an argument, returns a function, or both. JavaScript has always supported this. TypeScript adds the ability to describe, and enforce, the exact shape of those callback functions so the compiler catches mismatches before they become runtime bugs.

This lesson builds directly on everything you already know about function annotations, optional parameters, and overloads. By the end you will be writing the kind of event-handler wiring that appears throughout Excalibur's API.

What Makes a Function "Higher-Order"?

A function is higher-order when it treats other functions as values. That means at least one of the following is true:

  • Its parameter list includes a function type
  • Its return type is a function type
// Accepts a callback — higher-order
function onEnemyDestroyed(callback: () => void): void {
  // ... internal logic ...
  callback();
}

// Returns a function — also higher-order
function createMultiplier(factor: number): (value: number) => number {
  return (value) => value * factor;
}
ℹ
Note

The term "higher-order" comes from mathematics and functional programming. You do not need to use that label in your code. What matters is knowing how to type the pattern correctly.

Typing Callback Parameters

The most common pattern is a function that receives a callback. You describe the callback's shape using an inline call signature: a parameter list in parentheses followed by a return type. 

// Call signature syntax: (paramName: ParamType) => ReturnType
function runAfterDelay(ms: number, callback: () => void): void {
  setTimeout(callback, ms);
}

// Callbacks can receive arguments too
function onScoreChange(callback: (newScore: number) => void): void {
  // ... internal logic updates the score ...
  const updated = 42;
  callback(updated);
}

When you call onScoreChange, TypeScript already knows the callback will receive a number. You do not have to re-annotate the parameter inside the arrow function you pass in. 

// TypeScript infers that `score` is number — no annotation needed here
onScoreChange((score) => {
  console.log(`Score updated to ${score}`);
});
💡
Tip

This inference is called contextual typing. TypeScript reads the expected callback signature from the function you are calling and uses it to type the parameters of the arrow function you write inline. You will see this constantly when working with array methods and Excalibur event handlers.

The Function Type Anti-Pattern

TypeScript has a built-in type called Function (capital F). It accepts any callable value but tells you nothing about its parameters or return type. Avoid it. 

// Bad — TypeScript cannot check anything about this callback
function runCallback(fn: Function): void {
  fn(1, 2, 3); // no errors, even if fn expects no arguments
}

// Good — the shape is explicit and checked
function runCallback(fn: (a: number, b: number) => number): void {
  const result = fn(1, 2); // TypeScript verifies both the call and the return
  console.log(result);
}
⚠
Warning

Using Function silences the compiler on the entire callback. Mistakes in argument count and types will only surface at runtime. Always write an explicit call signature.

Type Aliases for Callback Shapes

When the same callback signature appears in multiple places, a type alias keeps things readable and consistent. 

// Define once
type CollisionHandler = (target: string, damage: number) => void;

// Reuse wherever needed
function onPlayerCollision(handler: CollisionHandler): void {
  const target = "spike-trap";
  const damage = 10;
  handler(target, damage);
}

function onEnemyCollision(handler: CollisionHandler): void {
  const target = "player";
  const damage = 25;
  handler(target, damage);
}
💡
Tip

Excalibur defines named types for its own event payloads (for example CollisionEndEvent, KillEvent). When you write actor.on("kill", (evt) => ...), contextual typing uses those definitions to type evt automatically.

Returning Functions

A higher-order function can also produce a function as its result. This is useful for creating specialised variants of a general behaviour, a pattern sometimes called a factory or closure. 

// Returns a configured damage calculator
function createDamageCalculator(baseDamage: number): (multiplier: number) => number {
  return (multiplier) => baseDamage * multiplier;
}

const swordDamage = createDamageCalculator(15);
const critHit = swordDamage(2); // 30
const normalHit = swordDamage(1); // 15

TypeScript infers the return type from the returned arrow function, so you often do not need to annotate it explicitly. Spelling it out, as above, is still good practice in public APIs because it documents the contract. 

// TypeScript infers the same shape even without the explicit return annotation
function createDamageCalculator(baseDamage: number) {
  return (multiplier: number) => baseDamage * multiplier;
}
// Hover in your editor: inferred as (baseDamage: number) => (multiplier: number) => number

Higher-Order Functions and Array Methods

The built-in array methods map, filter, and reduce are all higher-order functions. TypeScript uses the element type of the array to infer what each callback will receive. 

type Enemy = {
  name: string;
  health: number;
  isAlive: boolean;
};

const enemies: Enemy[] = [
  { name: "goblin", health: 30, isAlive: true },
  { name: "troll", health: 0, isAlive: false },
  { name: "dragon", health: 200, isAlive: true },
];

// map: transform each element — callback receives Enemy, returns string
const names: string[] = enemies.map((e) => e.name);

// filter: narrow the array — callback receives Enemy, returns boolean
const living: Enemy[] = enemies.filter((e) => e.isAlive);

// reduce: accumulate a value — callback receives (number, Enemy), returns number
const totalHealth: number = enemies.reduce((sum, e) => sum + e.health, 0);
📌
Remember

For reduce, always supply the initial accumulator value as the second argument. Without it, TypeScript widens the accumulator type to Enemy (the array element type) instead of number, which almost never matches what you want.

Combining Patterns: A Mini Event System

Here is a practical example that ties everything together. This is a simplified version of the event listener pattern that Excalibur uses internally. 

type EventName = "spawn" | "destroy" | "damage";
type EventHandler = (payload: T) => void;

// A registry that maps event names to lists of handlers
const listeners: Partial[]>> = {};

function on(event: EventName, handler: EventHandler): void {
  if (!listeners[event]) {
    listeners[event] = [];
  }
  // Cast needed because the registry stores EventHandler
  (listeners[event] as EventHandler[]).push(handler);
}

function emit(event: EventName, payload: T): void {
  listeners[event]?.forEach((handler) => {
    (handler as EventHandler)(payload);
  });
}

// Register handlers
on("spawn", (name: string) => console.log(`${name} spawned`));
on("damage", (amount: number) => console.log(`Took ${amount} damage`));

// Fire events
emit("spawn", "goblin");   // logs: goblin spawned
emit("damage", 15);        // logs: Took 15 damage
ℹ
Note

The <T> syntax introduces a generic type parameter. Generics in functions are covered in depth in the next lesson. For now, read EventHandler<T> as "a handler for whatever payload type T turns out to be."

Try It: Excalibur Playground

The snippet below registers typed event callbacks on an Excalibur actor. Read through the annotations to see how the patterns from this lesson appear in a real game context. Then try modifying the onKill callback to log the actor's name. 

import * as ex from "excalibur";

const game = new ex.Engine({ width: 800, height: 600 });

const enemy = new ex.Actor({
  x: 400,
  y: 300,
  width: 32,
  height: 32,
  color: ex.Color.Red,
});

// on() accepts a typed callback — contextual typing infers evt's shape
enemy.on("collisionstart", (evt: ex.CollisionStartEvent) => {
  console.log(`Collided with: ${evt.other.name}`);
});

// A reusable handler defined as a named function
function handleKill(evt: ex.KillEvent): void {
  console.log(`Enemy killed at position: ${evt.target.pos}`);
}

enemy.on("kill", handleKill);

// once() is also higher-order — fires the callback exactly one time
enemy.once("postupdate", (_evt: ex.PostUpdateEvent) => {
  console.log("First update tick complete");
});

game.add(enemy);
game.start();

Summary
  • A higher-order function accepts a function as a parameter, returns a function, or both.
  • Callback types are written as inline call signatures: (param: Type) => ReturnType.
  • Contextual typing means TypeScript infers callback parameter types from the surrounding function's signature, so you rarely need to re-annotate them at the call site.
  • Always use explicit call signatures instead of the bare Function type to preserve type safety inside callbacks.
  • Type aliases give reusable callback shapes a single, readable name and keep function signatures clean.
  • Array methods like map, filter, and reduce are higher-order functions, and TypeScript infers callback types from the array's element type automatically.

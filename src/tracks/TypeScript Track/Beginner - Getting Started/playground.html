Introduction

Before writing your first real game, you need a place to experiment safely — somewhere you can try an idea in seconds without touching your local project, breaking a build, or waiting for a install step. The Excalibur Playground is that place. Every interactive example in this course opens there, and the faster you're comfortable with it, the faster everything else clicks.

This lesson is a guided orientation. You'll learn what the three regions of the Playground do, which four controls you actually need, and — importantly — what the Playground is not designed for. That last part matters: knowing the limits of a tool is just as useful as knowing its features.

Anatomy of the Playground

The Excalibur Playground is a browser-based environment that runs TypeScript and Excalibur code live — no install, no build step, no local server required. When it loads you'll see three regions:

  • Code editor — A Monaco-based editor (the same engine that powers VS Code) with TypeScript syntax highlighting, autocomplete, and inline error squiggles. This is where you write or modify code.
  • Game canvas — The live preview. Excalibur renders here. It updates every time you click Run.
  • Controls — Buttons for Auto Save, Build & Run, Toggle Debug, and Share. Also, there are hotkeys available for loading different quick-start projects.
ℹ
Note

The Playground does not auto-run on every keystroke. You explicitly press Run (or the keyboard shortcut shown in the toolbar) to compile and execute. This is intentional — it lets you finish a thought before seeing the result.

Key Controls

You only need to know four things to be productive in the Playground:


// ▶  Run           — compile TypeScript and start the game
// ⟳  Toggle Debug  — show/hide the debug overlay with colliders
// 🔗 Share         — copies the playground link to your clipboard to send to a friend!
// ⌘  Autosave     — automatically updates the URL with a permalink on every run
💡
Tip

Use Share whenever you want to ask a question in the community Discord. A link to your exact broken code is worth a thousand screenshots.

What the Playground Is (and Isn't)

The Playground is optimized for learning isolated concepts quickly. A few things to keep in mind as you use it across the course:

  • It's ephemeral by default. Refreshing the page resets your code unless you used Share to save a permalink. Copy your work before closing the tab.
  • It uses a fixed Excalibur version. The version shown in the toolbar matches the version taught in this course. If you check the official Excalibur docs and see a newer API, don't panic — the concepts transfer even if method names shift.
  • It doesn't replace a local project. The Playground has no file system, no asset pipeline, and no module bundler. For real games you'll graduate to a local setup. The Playground is your scratchpad.
📌
Remember

When a lesson says "Try it in the Playground," that's not optional busy-work. Typing code — even code you fully understand — builds muscle memory that reading alone never does. Run every example. Then break it on purpose.

✏️ Exercise
Explore Every Control

Using the Playground embed above, work through each of the following steps in order. The goal is to touch every major control at least once so nothing feels unfamiliar when you need it mid-lesson.

  1. Click Run and confirm the game canvas shows a colored rectangle. Note the compile time shown in the toolbar.
  2. Click Toggle Debug. What new information appears on the canvas? Click it again to turn it off.
  3. Click Share. Open the link it generated in a new tab and confirm your code is there exactly as you left it.
  4. Make any small edit — change a number or a color — and click Run. Observe that the URL updates automatically (Autosave in action).

Expected result: You've used all four controls and have a saved permalink to your modified example.

Summary
  • The Playground has three regions: code editor, game canvas, and control buttons. You control execution with Run — it does not auto-run on every keystroke.
  • The four controls you need are Run, Toggle Debug, Share, and Autosave. Share is the most important for preserving and sharing work.
  • Playground code is ephemeral by default. Use Share to save a permalink before closing the tab, or copy code into your local project.
  • The Playground uses a fixed Excalibur version, has no file system or asset pipeline, and is not a replacement for a local project — it's a scratchpad for learning isolated concepts fast.
  • Running every example, and then deliberately breaking it, is the fastest way to build real understanding.

Two Languages, One Runtime

Here's the key insight: TypeScript is not a replacement for JavaScript. It's a layer on top of it. When you write TypeScript, a tool called the TypeScript compiler (tsc) strips away all the type annotations and produces plain JavaScript.

That JavaScript is what actually runs in the browser or in Node.js. The types exist only during development — they're a safety net that disappears at runtime. 


// What you write (TypeScript)
const playerName: string = "Hero";
const score: number = 0;

function levelUp(level: number): number {
  return level + 1;
}


// What the compiler produces (JavaScript)
const playerName = "Hero";
const score = 0;

function levelUp(level) {
  return level + 1;
}

Notice what disappeared: : string, : number, : number. The types are erased. The logic stays identical.

ℹ
TypeScript is a superset

All valid JavaScript is also valid TypeScript. You can rename any .js file to .ts and it will work — TypeScript just won't be checking types yet. You add types gradually.

Spotting TypeScript Syntax

TypeScript adds syntax that plain JavaScript doesn't have. Learning to recognize these patterns is the first step to reading TypeScript fluently.

Type Annotations

A colon followed by a type name tells TypeScript what kind of value a variable holds:


let health: number = 100;
let playerName: string = "Aria";
let isAlive: boolean = true;

Function Parameter Types

Parameters and return values can be typed:


function takeDamage(currentHealth: number, damage: number): number {
  return currentHealth - damage;
}

Interface Definitions

Interfaces describe the shape of an object:


interface Player {
  name: string;
  health: number;
  score: number;
}
💡
You'll learn all of these

Don't worry about understanding every piece of syntax right now. Each of these concepts gets its own dedicated lesson. This overview just helps you know what you're looking at.

The Development Workflow

When working with TypeScript, the typical workflow is:

  1. Write .ts files with type annotations
  2. Your editor checks types in real-time as you type
  3. The TypeScript compiler (tsc) compiles to .js
  4. The JavaScript runs in the browser or Node

In modern setups (like ExcaliburJS projects), step 3 happens automatically via build tools like Vite or webpack. You just write TypeScript and the tools handle the rest.

📌
Types exist at compile-time only

TypeScript's type information does not exist at runtime. You cannot access type names or interface definitions while your program is running — they're gone after compilation. This is why TypeScript errors appear in your editor, not in the browser console.

Summary
  • TypeScript compiles to JavaScript — the types are erased at runtime
  • All JavaScript is valid TypeScript (TypeScript is a superset)
  • Type annotations use the : syntax after variable and parameter names
  • Interfaces describe the shape of objects
  • Build tools like Vite handle TypeScript compilation automatically
